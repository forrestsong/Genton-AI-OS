## 1. 目标与范围

### 1.1 核心目标

为 **C4.3 PII 掩码模型**的训练、验收与部署提供统一的验收基准，确保：

1. **命中率 >90%**：在标准评估集上，PII 检测召回率（Recall）≥90%
2. **精确率 >85%**：避免过度掩码正常文本，保持可用性
3. **敏感类别全覆盖**：金融/健康/账号三大类及子类别无遗漏
4. **掩码回退路径可用**：模型失败时的规则库兜底方案验收
5. **性能边界**：端侧推理延迟 ≤50ms（P95），内存占用 ≤30MB

### 1.2 适用范围

本基准适用于以下场景的 PII 掩码验收：

| 场景 | 服务 | maskPii 参数 | 草案引用 |
|---|---|---|---|
| UI 树文本节点 | IAgentUiTreeService | 默认 true | D1 §3.1 |
| 屏幕捕获帧 OCR | IAgentScreenService | 可选（性能考虑） | D1 §4.1 |
| 通知正文 | IAgentNotificationService | 默认 true | D1 §5.1 |
| 记忆写入前 | IAgentMemoryService | 强制（长期记忆） | D4 §2.2 |
| 上下文 TOP_UI_SUMMARY | IAgentContextService | 源头掩码 | D8 §2.3 |

## 2. 敏感类别定义（三大类 + 子类别）

### 2.1 金融类（Finance）

| 子类别 | 定义 | 示例 | 检测要求 |
|---|---|---|---|
| 银行卡号 | 13-19 位数字，含 Luhn 校验 | `6222 0012 3456 7890` | 必检（Luhn 算法验证） |
| 信用卡 CVV | 3-4 位数字（卡号旁） | `123` | 上下文相关检测 |
| 银行账号 | 含"账号/Account"关键词 + 10-20 位数字 | `账号：6228480012345678` | 关键词 + 模式 |
| 金额 | ≥10000 的货币金额（含符号/单位） | `¥15,000.00`、`$50,000` | 数值 + 货币符号 |
| 交易流水号 | 16-32 位字母数字混合（含"交易/订单"） | `TXN202609081234567890` | 上下文 + 长度 |
| 支付密码 | 含"支付密码/交易密码" | `请输入支付密码：******` | 关键词强制掩码 |

**掩码策略**：
- 银行卡号：保留前 4 位 + 后 4 位，中间 `****`（如 `6222 **** **** 7890`）
- CVV/密码：全掩码 `***`
- 金额/流水：全掩码或保留量级（`¥1****` 表示万元级）

### 2.2 健康类（Health）

| 子类别 | 定义 | 示例 | 检测要求 |
|---|---|---|---|
| 身份证号 | 18 位（含校验位）或 15 位 | `110101199001011234` | 校验位验证 |
| 护照号 | 大写字母 + 7-9 位数字 | `E12345678` | 格式 + 长度 |
| 病历号 | 含"病历号/就诊卡"+ 数字 | `病历号：A001234567` | 上下文关键词 |
| 诊断结果 | 医学术语（糖尿病/高血压/肿瘤等） | `诊断：2 型糖尿病` | 医学词表（500+ 词） |
| 药品名称 | 含"片/胶囊/注射液" | `阿莫西林胶囊` | 医药词表 |
| 体检指标 | 血压/血糖/心率等 + 数值 | `血糖：7.2 mmol/L` | 指标词表 + 数值 |
| 基因信息 | ATCG 序列（≥20 个碱基） | `ATCGATCGATCGATCGATCG` | 生物序列模式 |

**掩码策略**：
- 身份证/护照：保留前 3 位 + 后 2 位
- 诊断/药品：敏感疾病全掩码（如艾滋/肿瘤），常见病保留大类（`**感染`）
- 基因信息：全掩码

### 2.3 账号类（Account）

| 子类别 | 定义 | 示例 | 检测要求 |
|---|---|---|---|
| 手机号 | 11 位数字（中国）或国际格式 | `13812345678`、`+86 138****5678` | 号段验证 |
| 邮箱地址 | RFC 5322 格式 | `user@example.com` | 正则表达式 |
| IP 地址 | IPv4/IPv6（私网除外） | `192.0.2.1`、`2001:db8::1` | IP 格式 + 私网过滤 |
| MAC 地址 | 6 组十六进制（冒号/短横线分隔） | `00:1A:2B:3C:4D:5E` | 格式匹配 |
| 用户名密码 | 含"用户名/密码/账号"标签 | `用户名：admin`、`密码：******` | 标签 + 相邻文本 |
| API 密钥 | 含"key/token/secret" + 长字符串 | `api_key=sk_live_xxxxx` | 关键词 + Base64 模式 |
| 私钥证书 | `-----BEGIN PRIVATE KEY-----` | PEM 格式块 | 头尾标记 |

**掩码策略**：
- 手机号：保留前 3 位 + 后 4 位（`138****5678`）
- 邮箱：保留用户名首字母 + 域名（`u***@example.com`）
- 密码/密钥/私钥：全掩码 `***`

### 2.4 跨类别敏感模式

| 模式 | 示例 | 检测逻辑 |
|---|---|---|
| 连续数字 ≥10 位 | `1234567890123` | 长数字串（疑似卡号/证件） |
| 混合大小写 + 数字 ≥16 位 | `aB3cD4eF5gH6iJ7kL8` | 疑似密码/令牌 |
| 含"验证码/动态码" | `验证码：123456` | 关键词强制掩码 |

## 3. 验收基准（五个维度）

### 3.1 命中率基准（Recall ≥90%）

**定义**：真实 PII 被正确检测的比例。

$$
\text{Recall} = \frac{\text{TP}}{\text{TP} + \text{FN}} \geq 0.90
$$

**分类别要求**：

| 类别 | 目标召回率 | 原因 |
|---|---|---|
| 金融类 | ≥95% | 高风险，漏检不可接受 |
| 健康类 | ≥92% | 涉及隐私敏感度极高 |
| 账号类 | ≥88% | 部分账号信息（如邮箱）可容忍有限泄露 |

**测试方法**：在 3.5 节评估集上逐样本标注 TP/FN，计算召回率。

### 3.2 精确率基准（Precision ≥85%）

**定义**：掩码输出中真实 PII 的比例（避免过度掩码）。

$$
\text{Precision} = \frac{\text{TP}}{\text{TP} + \text{FP}} \geq 0.85
$$

**容忍度**：
- 金融/健康类：宁可过掩码（Precision 可降至 80%）
- 账号类：避免误伤正常文本（Precision ≥90%）

**常见误报场景**：
- 日期误识别为身份证号（`20230101` vs `110101199001011234`）
- 订单号误识别为银行卡号（需 Luhn 校验过滤）
- 普通邮箱格式字符串（如 `contact@company`）

### 3.3 敏感类别覆盖率（100%）

**要求**：2.1-2.3 定义的所有子类别必须在评估集中有代表性样本，且无遗漏检测。

**验收方式**：
- 每个子类别至少 50 个正样本
- 每个子类别召回率单独计算，不得低于类别基准（3.1）

### 3.4 掩码回退路径验收

**场景**：模型推理失败、超时或不可用时，必须有规则库兜底。

**规则库基线**：
1. 正则表达式规则（15 个高危模式）
2. 关键词词表（金融 50 词、健康 500 词、账号 30 词）
3. Luhn 校验（银行卡）+ 身份证校验位

**验收标准**：
- 规则库单独测试召回率 ≥70%（保底能力）
- 模型 + 规则库联合召回率 ≥92%（互补增强）
- 规则库响应时间 ≤5ms（P99）

**测试用例**：
```python
# 示例：规则库兜底测试
test_cases = [
    ("银行卡：6222001234567890", True),   # Luhn 校验通过
    ("身份证：110101199001011234", True), # 校验位正确
    ("api_key=sk_live_abcdefg12345", True),  # 关键词匹配
    ("订单号：ORDER20230101", False),     # 非敏感
]
```

### 3.5 性能边界验收

| 指标 | 基准值 | 测试方法 |
|---|---|---|
| 端侧推理延迟 | P50 ≤20ms, P95 ≤50ms | 1000 次推理计时 |
| 内存占用 | 峰值 ≤30MB | Android Profiler |
| 模型大小 | ≤10MB | .tflite 文件大小 |
| CPU 占用 | 单核 ≤30%（推理期间） | systrace |

**测试环境**：
- 设备：中端 Android 设备（骁龙 778G 或同级）
- 输入：100-500 字符文本（模拟 UI 树节点）
- 并发：单线程顺序推理（无并发）

## 4. 评估集构建规范

### 4.1 数据来源

| 来源 | 比例 | 说明 |
|---|---|---|
| 模拟生成 | 40% | 脚本生成符合格式的 PII（保证覆盖） |
| 公开数据集 | 30% | CoNLL-2003、MSRA-NER（中文） |
| 内部标注 | 20% | 真实 UI 截图 OCR 标注（脱敏后） |
| 对抗样本 | 10% | 故意混淆的边界 case |

### 4.2 样本规模

| 集合 | 样本数 | 用途 |
|---|---|---|
| 训练集 | 10,000 条 | 模型训练（C4.3 负责） |
| 验证集 | 2,000 条 | 超参调优 |
| 测试集 | 3,000 条 | 最终验收（本基准） |

**测试集构成**：
- 金融类：1,000 样本（500 正样本 + 500 负样本）
- 健康类：1,000 样本
- 账号类：800 样本
- 混合/边界 case：200 样本

### 4.3 标注规范

**标注格式**：BIO 标签（Beginning, Inside, Outside）

```json
{
  "text": "我的银行卡号是 6222001234567890，请勿泄露。",
  "entities": [
    {"start": 8, "end": 24, "type": "BANK_CARD", "label": "B-FIN"},
    {"start": 9, "end": 24, "type": "BANK_CARD", "label": "I-FIN"}
  ],
  "masked_text": "我的银行卡号是 6222 **** **** 7890，请勿泄露。"
}
```

**标注质量控制**：
- 双人标注 + 第三人仲裁（不一致率 <5%）
- 每批次抽样 10% 复核

### 4.4 对抗样本设计

**目的**：测试模型鲁棒性，防止简单规则绕过。

| 类型 | 示例 | 预期行为 |
|---|---|---|
| 空格干扰 | `6222 0012 3456 7890` | 正确识别（去空格） |
| 全角数字 | `６２２２００１２３４５６７８９０` | 正确识别（归一化） |
| 拼音混淆 | `yinhangkahao: 622200...` | 识别（关键词拼音） |
| 符号分隔 | `卡号：6222-0012-3456-7890` | 正确识别（去符号） |
| 上下文缺失 | `1234567890123456`（无标签） | 疑似掩码（连续数字） |

## 5. 验收流程

### 5.1 验收阶段

| 阶段 | 时间点 | 责任方 | 产出 |
|---|---|---|---|
| 模型提交 | C4.3 完成 | 部门 C | .tflite 模型 + 推理代码 |
| 基准测试 | A3 门禁前 | 部门 E + H | 测试报告 |
| 性能验收 | 基准通过后 | 部门 H | 性能报告 |
| 集成验证 | A5.1 联调 | 部门 A + C | 端到端测试 |
| 最终验收 | A3 门禁 | 部门 E | 验收结论 |

### 5.2 验收通过条件

**必须全部满足**：
- ✅ 总体召回率 ≥90%
- ✅ 总体精确率 ≥85%
- ✅ 每个子类别召回率达标（3.1 表格）
- ✅ 规则库兜底召回率 ≥70%
- ✅ 性能指标全部达标（3.5 表格）
- ✅ 对抗样本准确率 ≥80%

**验收不通过处理**：
- 差距 <5 个百分点：给出改进建议，1 周内复测
- 差距 ≥5 个百分点：退回 C4.3 重新训练
- 性能不达标：优化推理引擎或简化模型

### 5.3 回归测试

**触发条件**：
- 模型版本更新（C4.3）
- 规则库更新（E3.1）
- Android 系统版本升级

**回归频率**：每季度一次 + 重大变更触发

## 6. 掩码策略实施细则

### 6.1 掩码强度分级

| 级别 | 策略 | 适用场景 |
|---|---|---|
| 强掩码 | 全替换 `***` | 密码/CVV/私钥/基因 |
| 中掩码 | 保留首尾，中间 `****` | 银行卡/身份证/手机号 |
| 弱掩码 | 保留大类/量级 | 诊断（`**感染`）、金额（`¥1****`） |
| 不掩码 | 原样输出 | 公开信息（公司名/地址） |

### 6.2 上下文敏感掩码

**规则**：同一实体在不同上下文中掩码强度可变。

**示例**：
```
// 场景 1：支付确认（高敏感）
"请确认向 6222 **** **** 7890 转账 ¥1****"  // 强掩码

// 场景 2：历史记录（低敏感）
"2023-09-01 向 招商银行(7890) 转账"        // 弱掩码（仅尾号）
```

**实现**：通过 `MaskContext` 参数传递场景标识。

### 6.3 可逆掩码（审计场景）

**需求**：审计事件需要原始 PII（经 TEE 加密存储）。

**方案**：
```kotlin
data class MaskedValue(
    val displayText: String,      // 掩码后文本（给 Agent/UI）
    val encryptedOriginal: ByteArray?,  // TEE 加密原文（审计用）
    val maskLevel: MaskLevel      // 掩码级别
)
```

**访问控制**：
- `displayText`：所有 Agent 可见
- `encryptedOriginal`：仅审计服务 + viewerRole=USER 解密读

## 7. 已知限制与开放问题

### 7.1 已知限制

1. **多语言支持**：v1 仅支持中文/英文，其他语言召回率未验收
2. **图片 OCR**：屏幕截图 OCR 后再掩码，延迟增加 100-200ms
3. **语音转写**：ASR 文本掩码准确率低于文本输入（C4.4 待评估）
4. **实体链接**：无法识别"小明的卡号"中"小明"与后续卡号的关联

### 7.2 开放问题

| 问题 | 当前处理 | 后续计划 |
|---|---|---|
| 跨模态 PII（图片中的卡号） | OCR + 文本掩码 | A4 期评估专用 OCR 模型 |
| 动态敏感词更新 | 规则库 OTA（C6.4） | A4 期实现 |
| 用户自定义敏感类别 | 不支持 | A5 期评估可行性 |
| 掩码后文本可读性 | 未量化评估 | 需要人因测试（H5.2） |
