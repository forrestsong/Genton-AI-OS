# G5.1 出网审计台与异常检测设计

> **任务编号**：G5.1
> **任务名称**：出网审计台与异常检测（预算超限、域名突变、票据滥用，逐调用审计汇入 A5.3 全链）
> **交付物**：审计台
> **前置依赖**：G1.2（模型分级路由与配额）、G2.2（票据生命周期与吊销）
> **草案来源**：D13（轨道A-端云调度与推理路由接口草案.md）、D4（轨道A-记忆服务与审计引擎接口草案.md §3 审计引擎）、A5.3（全服务审计埋点）
> **里程碑**：A4（生态与主动服务）
> **状态**：设计稿（待实现）

---

## 1. 摘要

出网审计台是云侧**逐调用审计 + 异常检测**的统一入口：把设备每一次云端调用（Broker 推理、attestation、删除传播、联邦贡献、OTA 拉取）的**审计摘要**汇集到云侧审计链，检测**预算超限、域名突变、票据滥用**等异常，并把逐调用审计汇入 A5.3 全链（端侧审计链 + 云侧审计链通过 requestId/deviceKeyHash 关联）。

设计要点：

1. **逐调用审计**：每次云端调用产生一条审计摘要（不落正文，D4 证据分层），含 requestId/字段清单/用量/结果码/票据信息。
2. **三类核心异常检测**：预算超限（配额滥用）、域名突变（出网行为漂移）、票据滥用（重放/盗用/异常频率）。
3. **汇入 A5.3 全链**：端侧审计（`IAgentAuditService` 哈希链 + TEE 锚定）与云侧审计摘要按 `requestId` 关联，形成端到端可追溯链路；云侧审计同样哈希链 + 周期锚定。
4. **告警联动**：异常触发告警 → G5.2 SRE 事件管理 / 安全响应（联动 G2.2 吊销）。

## 2. 职责

| 职责 | 说明 |
|---|---|
| 审计采集 | 接收各云服务（G1.1-G4.2）的逐调用审计摘要，统一 schema 归一化 |
| 审计链 | 云侧审计哈希链（seq + prevHash + 周期锚定，对齐 D4 §3.1），只增不改 |
| 异常检测 | 预算超限 / 域名突变 / 票据滥用三类检测器 + 规则引擎 |

| 审计台 UI | 查询/检索（按 viewerRole 脱敏）、告警视图、报表 |
| 告警联动 | 异常事件 → G5.2 事件管理；安全事件 → G2.2 吊销联动 |

## 3. 接口契约

### 3.1 审计写入（云服务 → 审计台）

端点：`POST /v1/audit/ingest`（内部接口，云服务调用）

```json
{
  "events": [
    {
      "requestId": "req_01HZ...",
      "deviceKeyHash": "sha256:9f2c...b1e0",
      "service": "broker",               // broker | attest | deletion | federated | ota | quota
      "operation": "responses_infer",
      "category": "CLOUD_INFERENCE",     // 对齐端侧 CAT_* 语义扩展
      "occurredAtMs": 1737000005000,
      "summary": {
        "modelId": "cloud-llm-v3-lite",
        "fieldsSent": ["prompt", "context"],
        "privacyMode": "masked",
        "crossBorder": false,
        "usage": { "inputTokens": 320, "outputTokens": 96, "costMicros": 2300 },
        "ticketId": "tkt_8f3a...",
        "quotaCheck": "ALLOWED",
        "resultCode": "OK"
      },
      "payloadHash": "5f2a...9c",        // 证据引用（不落正文）
      "evidenceRef": "broker:req_01HZ..."
    }
  ]
}
```


## 4. 异常检测器

### 4.1 预算超限检测（对齐 G1.2 配额 + 纵深）

| 检测器 | 逻辑 | 阈值（示例） | 动作 |
|---|---|---|---|
| 日预算超限 | 单设备日成本 > 账户级日预算 | 1.5× 日预算 | warning → 限流 |
| 会话突增 | 单会话成本斜率异常 | 斜率 > 3× 基线 | warning |
| 预算突变 | 设备月成本环比突增 | > 5× 上月均值 | high → 暂停云推理 |
| 配额碰撞 | 频繁触发 BUDGET_EXCEEDED 后仍重试 | > 10 次/小时 | high → 审计 + 限流 |

### 4.2 域名突变检测（对齐 D13 域名白名单）

| 检测器 | 逻辑 | 动作 |
|---|---|---|
| 非白名单域名 | 设备请求解析到白名单外域名 | critical → 阻断 + G2.2 联动 |
| 域名集突变 | 单设备访问的 Broker/上游域名集合变化 | 与基线比对，突增 → warning/high |
| DNS 异常 | 设备解析结果与地域预期不符 | warning → 复核 |
| 证书指纹突变 | 设备连接的服务端证书指纹非预期 | critical → 阻断（G2.2 端侧白名单联动） |

### 4.3 票据滥用检测（对齐 G2.2）

| 检测器 | 逻辑 | 动作 |
|---|---|---|
| 重放检测 | 同一 ticketId 高频使用 / 跨地域使用 | high → 吊销票据（G2.2） |
| 频率异常 | 单设备请求频率 > 设备速率配额 N 倍 | warning → 限流 |
| 并发异常 | 单设备并发会话突增 | high → 审计 |
| 盗用检测 | 票据使用 IP/设备指纹与签发时不符 | critical → 吊销 + 重新证明 |
| 已吊销票据使用 | 使用吊销后票据 | critical → 告警 + 审计（G2.2 生效验证） |

## 5. 逐调用审计汇入 A5.3 全链

```
端侧（D4/A5.3）                           云侧（G5.1）
IAgentAuditService（哈希链+TEE锚点）         云侧审计链（哈希链+周期锚定）
  ├─ 感知/动作/策略/记忆/确认/系统 7 类         ├─ CLOUD_INFERENCE / ATTEST / DELETION /
  ├─ EgressPlan 摘要（出网前）                  ├─  FEDERATED / OTA / QUOTA
  └─ requestId ──────────────────────────────►  └─ requestId（关联键）
                                                    deviceKeyHash
  端到端追溯：requestId 贯穿两端，证据分层（端侧正文 + 云侧摘要）
```

- **关联键**：`requestId`（同一次云端调用两端一致）+ `deviceKeyHash`（设备维度）。
- **全链校验**：端侧 `verifyChain`（D4）与云侧 `chain.verified` 独立校验；端云关联视图可交叉验证（一次调用两端都有记录，缺失即异常）。
- **A5.3 对齐**：云侧审计 category 扩展端侧 7 类 schema（`AuditEvent` 的 schema 只增不改，D4 §3.1），新增 `CLOUD_*` 类目。
- **viewerRole 脱敏**：审计查询按 viewerRole 过滤（对齐 D4：用户仅摘要级，管理员全量，正文永不落云侧审计）。

## 7. 安全边界

- **审计链只增不改**：云侧审计哈希链不可删除/修改（对齐 D4 R8.2/R8.4）；周期锚定（TEE/HSM 锚点）。
- **不落正文**：审计只含摘要 + payloadHash + 证据引用（D4 §3.1 证据分层），正文按 G3.1/G3.2 处理。
- **viewerRole 脱敏**：查询按角色过滤；用户可见摘要级。
- **检测器防绕过**：检测基于服务端权威数据（配额计数/票据状态/域名解析），设备不可篡改。
- **告警防风暴**：告警聚合/去重/抑制（同设备同类告警合并，防告警疲劳）。
- **关联完整**：requestId 缺失的调用（端云不匹配）视为异常（可能绕过端侧审计）。
- **审计写入鉴权**：ingest 仅云服务内部可调（mTLS 服务间认证）；设备不可直接写云审计。

## 8. 部署形态

- 审计台 = 采集服务（无状态，Kafka 事件流）+ 云侧审计链存储（只增不改存储）+ 检测引擎 + 查询 UI。
- 事件流支持高吞吐（逐调用）；检测引擎（规则 + 基线学习）可横向扩容。
- 审计链锚定服务（HSM/TEE 锚点，周期批处理）。
- 与 G5.2 监控、G2.2 吊销、G3.1 删除共用事件总线；告警路由到 SRE/安全值班。
- 审计存储地域按 G3.2 配置（审计摘要地域驻留）。

## 9. 与端侧联动

| 端侧 | 联动点 |
|---|---|
| `IAgentAuditService`（D4） | 端侧审计链（7 类事件 + EgressPlan 摘要）与云侧审计按 requestId 关联 |

| `IAgentInferenceRouter` | 预算硬上限（端侧）与云侧预算异常检测双端联动 |
| G2.2 吊销 | 票据滥用检测 → 吊销联动（设备端白名单同步更新） |

## 10. 验收口径

- [ ] 逐调用审计采集齐全：Broker/attestation/删除/联邦/OTA/配额六类服务全覆盖
- [ ] 云侧审计哈希链完整：verifyChain 通过、周期锚定生效、只增不改
- [ ] 预算超限/域名突变/票据滥用三类检测器命中并告警（阈值生效）
- [ ] 域名白名单外连接 → critical 阻断 + G2.2 联动
- [ ] 票据滥用（重放/盗用/已吊销使用）→ 吊销联动（≤1min，R9.9）
- [ ] requestId 端云关联视图可查；缺失关联（一端缺记录）→ 异常告警
- [ ] viewerRole 脱敏生效（用户摘要级、管理员全量）；正文不落云审计
- [ ] 告警聚合/去重生效（无告警风暴）
- [ ] 审计 ingest 鉴权：设备不可直接写云审计

## 11. 遗留项

1. **基线学习**：域名/预算"突变"需要动态基线（按设备/时段学习），冷启动基线缺失期的误报率待实测。
2. **检测规则参数化**：阈值表需按 H5.1 遥测数据校准（对齐 G1.2 遗留项 1）。
3. **安全响应 SOP**：critical 告警的人工处置流程（暂停/吊销/恢复）需与 G5.2 事故管理联动定义。
4. **审计链锚定频率**：云侧审计链锚定周期（对齐端侧 D4 开放问题 5）待定。
5. **多供应商审计**：上游供应商侧审计可见性（供应商故障/异常调用）待 G1.1 遗留项 1 联动。
