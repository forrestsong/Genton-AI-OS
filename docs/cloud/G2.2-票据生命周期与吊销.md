# G2.2 票据生命周期与吊销设计

> **任务编号**：G2.2
> **任务名称**：票据生命周期与吊销（设备丢失/撤销、吊销下发、端侧白名单联动）
> **交付物**：票据管理服务
> **前置依赖**：G2.1（设备远程证明服务端）
> **草案来源**：D13（轨道A-端云调度与推理路由接口草案.md）、密钥管理与签名方案.md（CRL/轮换）
> **里程碑**：A3（智能与端云）
> **状态**：设计稿（待实现）

---

## 1. 摘要

票据生命周期与吊销管理覆盖**从设备证书签发、票据签发/刷新/过期，到吊销（设备丢失/用户撤销/密钥泄露）的完整链路**。核心目标：

1. **吊销实时生效 ≤1 分钟**（红线 R9.9）：设备丢失或撤销后，云端在 1 分钟内拒绝其所有票据与请求。
2. **吊销下发**：云端吊销事件通过**推送（长连接/WebSocket）+ 拉取（CRL 快照）双通道**下发到 Broker 与设备端。
3. **端侧白名单联动**：设备端维护**云端服务白名单**（域名+证书指纹，D13 §4）；云端吊销设备后，设备端同步更新本地信任状态（如吊销本设备的票据缓存、拒绝被吊销的 Broker 服务端票据）。

---

## 2. 职责

| 职责 | 说明 |
|---|---|
| 票据状态机 | 签发 → 有效 → 刷新（次数限制）→ 过期/吊销/撤销 |
| 吊销管理 | 设备丢失/被盗/用户撤销/证书泄露 → 吊销设备证书与全部未过期票据 |
| 吊销下发 | 推送（Broker 长连接事件流）+ 拉取（CRL 快照，5 分钟粒度兜底）；Broker 侧吊销缓存实时生效 |
| 端侧白名单联动 | 向设备下发"吊销/信任更新"指令：设备更新本地信任列表（拒绝连接被吊销的 Broker、清除本机票据缓存） |
| 吊销审计 | 吊销原因/操作者/生效时间全审计（G5.1 票据滥用检测输入） |
| CRL 管理 | 设备证书 CRL（对齐密钥方案 §5.2 格式），定期发布 + 签名 |

## 3. 接口契约

### 3.1 吊销（管理面）

端点：`POST /v1/ticket/revoke`（管理面；用户侧经账号体系/客服工单触发）

```json
{
  "revocationId": "rev_01HZ...",
  "target": { "deviceKeyHash": "sha256:9f2c...b1e0" },
  "reason": "device_lost",               // device_lost | device_stolen | user_revoke | key_compromise | account_closure
  "operator": "user_self_service",
  "immediate": true,                     // true=即时吊销全部票据；false=仅证书 CRL（票据自然过期）
  "notifyDevice": true                   // 是否下发设备端白名单更新
}
```

响应：

```json
{
  "revocationId": "rev_01HZ...",
  "status": "REVOKED",
  "effectiveAtMs": 1737000000000,
  "affectedTickets": 7,
  "brokerPropagation": { "pushed": 3, "pendingPull": 2 },
  "deviceNotify": "SENT"
}
```

### 3.2 吊销事件流（云 → Broker）

Broker 订阅吊销事件（长连接推送）：

```json
{
  "eventType": "ticket.revoked",
  "revocationId": "rev_01HZ...",
  "deviceKeyHash": "sha256:9f2c...b1e0",
  "effectiveAtMs": 1737000000000,
  "reason": "device_lost",
  "seq": 88421
}
```

### 3.3 吊销/信任更新下发（云 → 设备）

端点：设备出网检查更新：`GET /v1/trust/check?sinceVersion=N`（或长连接推送）

```json
{
  "trustListVersion": 12,
  "updates": [
    {
      "type": "revoke_ticket_cache",
      "deviceKeyHash": "sha256:9f2c...b1e0",   // 本设备被吊销 → 清除本机票据缓存
      "effectiveAtMs": 1737000000000
    },
    {
      "type": "broker_untrusted",
      "brokerId": "broker-cn-north-1",
      "reason": "cert_compromised",            // 某 Broker 服务端证书泄露 → 端侧白名单剔除
      "certFingerprint": "sha256:AA..."
    }
  ],
  "signature": "<AS 私钥签名>"
}
```

端侧 `CloudGateway` 处理：校验签名 → 按类型更新本地白名单/缓存 → 审计本地事件（联动端侧 `IAgentAuditService`）。

### 3.4 设备证书 CRL

对齐密钥方案 §5.2 CRL 格式（签名 + 吊销证书序列号列表），设备证书 CRL 每 5 分钟刷新：

```json
{
  "version": "1.0",
  "type": "device_cert_crl",
  "last_update": "2026-09-05T00:00:00Z",
  "next_update": "2026-09-05T00:05:00Z",
  "revoked_certificates": [
    { "serial_number": "0x3F2A...", "revocation_date": "2026-09-05T00:00:01Z", "reason": "key_compromise" }
  ],
  "signature": "..."
}
```

## 4. 票据生命周期状态机

```
                    ┌──────────┐
  register/verify ─►│  ISSUED   │
                    └────┬─────┘
                         │ (有效期内)
              ┌──────────┼──────────┐
              ▼          ▼          ▼
          refresh    expire     revoke
       (≤maxRefresh)   │          │
              │         ▼          ▼
              └──►  EXPIRED    REVOKED (即时，≤1min 全局生效)
```

| 状态 | 触发 | 处理 |
|---|---|---|
| ISSUED | G2.1 证明通过 | 短时效（≤5min），scope 限定 |
| REFRESHED | 票据到期前刷新 | 次数上限（如 5 次）；刷新需非重复 nonce |
| EXPIRED | TTL 到期 | Broker 拒绝（401）；设备重新证明 |
| REVOKED | 吊销事件 | 全局缓存生效 ≤1min；Broker 拒绝；设备端同步清除 |

## 6. 安全边界

- **吊销实时性**：Broker 吊销缓存（内存 + 分布式发布订阅）生效 ≤1 分钟（R9.9）；拉取 CRL 兜底 5 分钟粒度（可配置）。
- **防吊销绕过**：吊销以 `deviceKeyHash` + 设备证书序列号双重锚定；已吊销设备即使伪造新票据（无 AS 私钥）也无法通过验签。
- **指令签名**：设备端信任更新指令带 AS 签名，端侧验签后才执行（防伪造吊销/恶意白名单注入）。
- **最小泄露**：吊销指令只含 deviceKeyHash/证书指纹，不含用户身份。
- **撤销记录完整性**：吊销操作不可删除、不可修改（对齐 R11.14 撤销日志）；审计链只增不改（D4）。
- **重放防护**：吊销事件流带 seq，设备/Broker 去重。
- **端侧白名单联动**：设备端证书固定（密钥方案 §5.1）+ 域名白名单（D13 §4）是联动基础；Broker 服务端证书泄露 → 设备端剔除该 Broker 指纹，杜绝设备连向被攻破的服务端。

---

## 7. 部署形态

- 票据管理服务与 G2.1 AS 同集群（共享设备注册表/CRL/吊销状态存储）。
- 吊销事件流走消息总线（Kafka/自研事件流），Broker 集群订阅；设备端经出网检查通道拉取/推送。
- CRL 快照放 CDN（签名 + 短 TTL），设备/Broker 可低成本拉取。
- Broker 吊销缓存：本地内存（秒级） + 事件总线（实时推送），冷备 Redis。

## 8. 与端侧联动

| 端侧 | 联动点 |
|---|---|
| `CloudGateway` | 出网前检查本地信任列表（含吊销状态）；缓存设备票据并在吊销指令到达时清除 |
| 端侧域名白名单 | 吊销的 Broker 指纹从白名单剔除；只连白名单内 AS/Broker（D13 §4） |
| `IAgentInferenceRouter.attestDevice()` | 设备被吊销后重新证明 → `STATUS_ATTESTATION_FAILED` / 证书吊销错误 |
| 端侧审计（`IAgentAuditService`） | 白名单更新/票据清除事件落本地审计链（G5.1 对账） |
| 密钥方案 CRL | 设备证书 CRL 与平台证书 CRL 统一管理（密钥方案 §5.2） |
| A5.1 记忆服务 | 设备丢失后用户可触发"忘记并注销"→ 云端删除传播（G3.1）+ 吊销联动 |

## 9. 验收口径

- [ ] 吊销事件 Broker 侧生效 ≤1 分钟（R9.9）；拉取 CRL 兜底 ≤5 分钟
- [ ] 已吊销设备持旧票据请求 → 403 `TICKET_REVOKED`（G1.1 错误码映射）
- [ ] 设备端白名单/票据缓存按指令更新，指令签名校验失败则拒绝执行
- [ ] 吊销操作全审计（原因/操作者/生效时间），不可修改删除（R11.14）
- [ ] Broker 服务端证书泄露 → 设备端剔除该 Broker 指纹联动验证
- [ ] 吊销后重新证明流程：设备证书被吊销 → 重新注册流程（或恢复流程）可验证
- [ ] 吊销事件流 seq 去重，无重复/遗漏处理

## 10. 遗留项

1. **设备找回**：设备丢失后找回的恢复流程（重新激活 + 解除吊销）待产品定义。
2. **吊销传播的端到端 SLA 量化**：从吊销触发到设备端白名单更新完成的端到端时限需实测（当前仅 Broker 侧 ≤1min 有红线）。
3. **离线设备吊销**：长期离线设备再次联网时的强制吊销检查（联网首检信任列表版本）细节待定。
4. **批量吊销**：固件漏洞导致的大规模证书吊销的批量下发与回滚策略待定。
5. **与账号体系的绑定**：deviceKeyHash ↔ 账号/订阅的绑定变更流程（换绑/转卖）需与 G3.2 数据处置联动。
