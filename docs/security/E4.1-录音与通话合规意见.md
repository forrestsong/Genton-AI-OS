## 2. 核心合规原则（本意见的总纲）

1. **「告知 + 同意」是录音/转写的强制前置**：对来电方的任何录音/转写/留存，必须使其**知情**（开场白告知）+ **可行使其权利**（退出/拒绝/转真人）。这是 PIPL「单独同意」在通话场景的可执行落地：**来电方持续通话 = 默示同意，但其必须已被明确告知**；若来电方要求不录/挂断，系统必须尊重（fail-safe 到可见）。
2. **用户（被叫方）与来电方双重角色**：用户（手机主人）是 CallGate 的授权主体（逐项授权开启）；来电方是录音/转写的**相对方**，其知情权不能被用户授权所覆盖——**用户授权开启 L1/L2 ≠ 免除对来电方的告知义务**。
3. **本地优先 + 不出端**：通话音频/转写/摘要默认本地处理（R11.5），不落长期记忆、不上云；确需上云（如未来跨端同步）需单独同意 + 加密 + E4.2 跨境合规。
4. **审计与可追溯**：每通被接管来电审计（ruleId/时长/是否留言/摘要哈希），用户可在隐私仪表盘查看「谁替我对谁说过什么」（不采正文）。

## 3. 开放问题关闭决议（D16 §9）

### 3.1 开放问题 9.1：来电方知情与地区法律差异

**关闭决议**：

1. **开场白告知文案（默认，L1/L2）**：
   > 「你好，我是 {用户姓名} 的 AI 助理，正在帮你接听。**本次通话由 AI 接听并做文字记录用于给你摘要，通话不会被存储**。需要真人接听请说『转人工』或直接挂断。」
   - 三段信息必须齐全：① AI 身份披露（C2）；② 记录/转写告知（C1）；③ 不存储声明 + 真人出口（C2-④）。
2. **录音同意形态**：
   - **L1/L2 开启时**：开场白即告知，来电方继续说话 = 对该次转写/摘要的默示同意（中国司法实践：通话录音「一方同意」即可采证，但作为录音方应告知相对方）；**若来电方明确表示「不要记录」→ 系统立即停止转写/摘要，回退到纯人工接听或挂断（不记录）**。
   - **「录音」与「转写」区分**：转写（ASR 本地文本）比录音（音频文件）敏感度低但仍属个人信息处理，同样需告知；**录音（音频文件）默认不存**（D16 §6），除非用户显式开启「录音存档」并再次授权（录音则来电方告知增加「正在录音」）。
3. **地区差异处理**：
   - 中国首发：以上「告知 + 默示同意 + 可拒绝」基线；录音存档场景按 PIPL 单独同意 + 可选。
   - 出海（美国）：**two-party consent 州**（如加州）对「录音存档」需双方同意，开场白告知 + 来电方同意记录；转写若仅本地瞬时（不留存音频）风险较低但仍在告知范围。
   - 出海（欧盟）：GDPR Art.6/9——通话转写属通信内容处理，需合法基础（用户同意 + 来电方告知），本地处理减小风险。
   - **处理机制**：合规配置随地区 OTA（策略包/地区配置），`GateMode` 增加 `jurisdiction` 维度；**未配置地区合规时默认最严（告知 + 不录音存档）**（fail-safe）。

### 3.2 开放问题 9.1 附：AI 语音披露

**关闭决议**：

- **TTS 声音禁止伪装真人**：开场白/代接对话中 TTS 生成的语音必须传达 AI 身份（文字含「AI 助理」+ 声音不带真人名号/不冒充特定真人）。
- 对齐《人工智能生成合成内容标识办法》：AI 生成的音频对外呈现时应有**显式标识**——在通话场景体现为开场白文字披露（语音流无法叠加水印，用文字披露替代）；若未来通话摘要/录音对外共享，须保留「AI 生成/转写」标识。
- 反骚扰合规：**禁止用 AI 语音伪装真人进行营销/外呼**（本系统 CallGate 只处理**来电**，不发起 AI 外呼——明确边界：`classifyIncoming` 仅来电，拨出侧无 AI 外呼能力）。

### 3.3 开放问题 9.2：telecom/InCall 深度定制（双卡/Wi-Fi Calling）

**关闭决议**：

- **合规口径已定**（不受技术可行性影响）：无论音频桥是否可行，以上 §3.1 告知义务都成立；音频桥不可行的机型**回退原生响铃**（fail-safe 到可见，不静默）。
- **DND 双卡（R11.8）**：双卡各自维护 `GateMode` 与白名单：
  - `GateMode` 增加 `simSlot`（0/1）维度；DND 模式下每卡可独立设置「仅白名单响铃」；
  - **紧急号码在双卡均不可拦**（R11.6，baseline 覆盖所有 slot）。
- **Wi-Fi Calling / VoLTE**：音频桥可行性列入机型矩阵（A12.2 能力位登记 `CALLGATE_AUDIO_BRIDGE`）；不可行降级为「无音频桥的来电元数据判定 + 原生响铃」。

### 3.4 开放问题 9.3：音频延迟预算

**关闭决议**：

- 保留 D16 §9.3 目标：**接起→开场白（TTS）≤1s、留言→首转写 ≤1s（P95）**，作为 H 部门验收项（H3.5 相关）。
- 合规要求：若延迟导致开场白未及播放（来电方已说话），**必须在转写结果上标记「未确认同意」**（来电方未听到告知即说话）——该段转写只用于当通摘要，**不得留存为录音证据**（合规灰度）。

### 3.5 开放问题 9.4：反骚扰模型门槛

**关闭决议**：

- **spamScore ≥0.9 为 L1/L2 接管的最低触发门限**（D16 草案），保持；
- **误拦度量**：误拦（真人被 AI 接管且无告知/被折叠）属红线风险——任何「高置信广告」判定进入接管前，**必须仍播放开场白**（即使 spamScore 高）；「静默过滤（不响铃、无任何提示）」**禁止用于未知号码**（缺省 RING_NATIVE，D10 §4.1）；
- 反骚扰模型只作为「路由参考」，**不豁免来电方告知义务**（模型判定「广告」不代表可静默录音）。

### 3.6 开放问题 9.5：通话摘要与第三方 Agent 边界

**关闭决议**：

- **默认禁止**：通话摘要/转写/建议回拨卡**不得经第三方 Agent（D14 沙箱）呈现或转发**（D16 §9.5 倾向确认）；
- 例外需「显式授权评审」：用户明确授权某个第三方场景（如「允许我的工作助理读通话摘要」），须满足：三方 Agent 经 `IAgentSandboxGateway` 受限读 + 该读操作审计 + 摘要已脱敏（不含电话号码原文，仅 `callbackNumberMasked`）。

### 3.7 开放问题 9.6：RECORD_ONLY（L3）价值边界

**关闭决议**：

- L3「仅记录 + 建议回拨」的**记录对象 = 来电事件元数据**（时间/号码掩码/来源分类）+ 用户授权的留言或摘要，**不是静默录全通话**；
- 「建议回拨时机」输入 = 历史回拨习惯（S1 本地学习，仅系统大脑可读）+ 当次摘要，**不引入跨 Agent 数据**；
- 合规：无录音时 L3 不需要来电方同意（元数据记录属用户自己的通话记录），但**号码掩码**必须（`numberMasked`）。

### 3.8 紧急号码保底（R11.6，非 D16 开放问题但关键红线）

**关闭决议**：

- 系统基线 `sys.callgate.baseline.emergency`（DSL §7.2）：紧急/系统号码 → `RING_NATIVE` + `baselineGuard=true`，**优先级 1000 且不可被 user/learn 规则覆盖**（D10 冲突裁决）；
- **数据面保护**：紧急号码集合由系统写死（`WhitelistEntry.relation=emergency`、`systemProtected=true`），用户不可删（D16 `removeWhitelistEntry` 返回 `STATUS_DENIED`）；
- **任何模式（L1/L2/L3/关闭）都不拦截紧急号码**；DND 双卡场景紧急号码两卡均响铃。

## 4. 录音告知与授权 UI 验收要求（R11.1/R11.4/R11.7）

### 4.1 用户侧授权 UI（设置）

| 项 | 要求 |
|---|---|
| 逐项授权 | L1/L2/L3 独立开关 + 号码范围（全部/未知/号段/联系人分组）× 模式；授权记录进策略引擎 `call_gate` 域 enablement 条目，可随时撤销/一键关闭 |
| 录音存档 | 独立授权项（默认关）；开启后每通录音仅本地加密（密钥 Keystore），来电方告知增加「正在录音」 |
| 双卡配置 | 每卡独立 GateMode/白名单（§3.3） |
| 紧急号码 | 只读展示（不可删），可见性提示「系统保护」 |

### 4.2 来电侧 UI（接管中）

| 项 | 要求 |
|---|---|
| 接管卡 | 显示「AI 接管中」+ 来电方来源（掩码）；替代原生响铃 |
| 开场白 | 系统签发（`greetingTextRef`，防注入，D16 §4），含 §3.1 三段信息 |
| 活性指示 | 转写/录音期间全局指示器常显（R11.4，复用 D3.2）；录音态明确标识「正在录音」（若开启） |
| 真人出口 | 来电方说「转人工」→ 回退原生通话；用户侧可随时接管/挂断 |
| 每通审计 | `CAT_SYSTEM`（ruleId/时长/是否留言/摘要哈希），仪表盘可见 |

### 4.3 验收方法

- 用例「开启 L1 + 未知号码来电 → 开场白含 AI 披露 + 记录告知 + 真人出口」；
- 用例「来电方说『不要记录』→ 转写停止、回退人工、不落任何留存」；
- 用例「紧急号码在 L1/L2/DND 下 → 永响铃（RING_NATIVE）」；
- 用例「双卡各自模式 → 卡 1 L1 / 卡 2 DND 独立生效，紧急号码两卡均响」；
- 用例「录音存档关闭 → 通话后 `find /data -name '*.m4a'` 为空」；
- 用例「转写/摘要不出端 → 网络抓包无通话内容（联动 H3.4）」。

| 通用 | 地区配置缺失 | **默认最严（告知 + 不录音存档）**（fail-safe） |

## 6. 遗留项（非阻断，随里程碑）

1. **法务终审**：开场白文案与录音同意形态在上市前经法务终审（D16 §9.1 既定）。
2. **音频桥机型矩阵**：Wi-Fi Calling/VoLTE 音频桥可行性登记（A12.2 能力位）。
3. **录音存档的取证与解锁流程**：用户开启录音存档后的证据导出规范（对齐 D4 §6 证据解锁）。
4. **通话摘要的长期价值评估**：L3「建议回拨时机」的收益/隐私边界随 S1 学习演进评估。
