# G2.1 设备远程证明服务端设计

> **任务编号**：G2.1
> **任务名称**：设备远程证明服务端（attestation 校验、设备票据签发/刷新）
> **交付物**：证明服务
> **前置依赖**：E2.3（端云安全基线评审）
> **草案来源**：D13（轨道A-端云调度与推理路由接口草案.md）、E2.2（TEE 接入评审）
> **里程碑**：A3（智能与端云）
> **状态**：设计稿（待实现）

---

## 1. 摘要

设备远程证明服务端（Attestation Service，AS）是端云信任链的**根服务**：负责校验设备端 `IAgentInferenceRouter.attestDevice()` 产生的 `AttestationReport`（quote），确认设备运行在**未被篡改的 TEE/可信环境**且持有**平台签发的设备身份证书**，校验通过后签发**设备票据**（短时效，供 CloudBroker 会话使用）。

设计目标：

1. **双向证明**：设备向云证明"我是合法未篡改设备"；云向设备证明"我是合法 Broker"（G1.1 服务端证书固定）——双向信任（D13 §4）。
2. **零信任**：每次会话首包携带 quote；AS 校验后发放短时效票据，Broker 不重复校验 quote（票据即信任凭证）。
3. **证明开销 ≤100ms P95**（红线 R9.10）：证明 + 握手全链路在预算内。
4. **最小指纹泄露**：以 `deviceKeyHash`（设备公钥哈希）作为身份主键，不传输完整设备 ID（A9.1 实现口径）。

---

## 2. 职责

| 职责 | 说明 |
|---|---|
| quote 校验 | 校验设备 TEE 产出的 attestation quote（OEM TEE：Android Keystore attestation / StrongBox / 自研 TEE），验证签名链与 PCR/声明 |
| 设备身份校验 | 校验设备身份证书（平台根证书签发的设备证书，见密钥方案）有效性、是否吊销（CRL/G2.2） |
| 设备注册表 | 维护已注册设备状态（首次注册/换绑/注销）；`deviceKeyHash` ↔ 账户/订阅绑定 |
| 票据签发 | 证明通过后签发**设备票据**（短时效、作用域限定、带签名），供 Broker 会话握手使用 |
| 票据刷新 | 短时效票据到期前可刷新（延长会话），刷新需重新校验 quote（或降频校验，见遗留项 1） |
| 证明审计 | 每次证明请求/结果落审计摘要（G5.1 → A5.3） |

## 3. 接口契约

### 3.1 证明校验与票据签发

端点：`POST /v1/attest/verify`（HTTPS + mTLS；设备首包调用）

请求（设备端 `attestDevice()` 输出映射）：

```json
{
  "protocolVersion": "1",
  "deviceKeyHash": "sha256:9f2c...b1e0",
  "attestation": {
    "type": "TEE",                    // software | TEE | hardware
    "quote": "<base64 quote>",        // 端侧 AttestationReport.quote
    "signature": "<base64 设备私钥签名>",
    "nonce": "f0e1d2c3b4a59687",
    "timestampMs": 1737000000000
  },
  "clientCertChain": ["<mTLS 客户端证书链>"],
  "deviceModel": "ANE-100",
  "osVersion": "1.0.0",
  "teeVendor": "strongbox_v2",
  "requestedScope": ["responses", "realtime", "transcribe"],
  "requestedTtlMs": 300000              // 建议票据时长（服务端有最终决定权）
}
```

响应（成功）：

```json
{
  "result": "VERIFIED",
  "deviceTicket": {
    "ticketId": "tkt_8f3a...",
    "deviceKeyHash": "sha256:9f2c...b1e0",
    "scope": ["responses", "realtime", "transcribe"],
    "issuedAtMs": 1737000000000,
    "expiresAtMs": 1737000300000,      // 短时效：默认 5 分钟
    "maxRefreshCount": 5,
    "signature": "<AS 私钥签名>"
  },
  "attestationLevel": "HARDWARE_TEE",   // 证明强度分级
  "nextProofDueMs": 1737000000000       // 下次强制重新证明时间（票据过期）
}
```

响应（失败）：

```json
{
  "result": "FAILED",
  "error": {
    "code": "QUOTE_INVALID",           // QUOTE_INVALID | CERT_REVOKED | DEVICE_UNREGISTERED | NONCE_STALE | SIGNATURE_INVALID
    "message": "quote 签名校验失败或 PCR 声明不匹配",
    "retryable": true
  }
}
```

### 3.2 票据刷新

端点：`POST /v1/attest/refresh`（HTTPS + mTLS + Bearer 旧票据）

```json
{
  "ticketId": "tkt_8f3a...",
  "deviceKeyHash": "sha256:9f2c...b1e0",
  "refreshNonce": "a1b2c3d4e5f6a7b8",
  "reProof": { "quote": "<可选：降频场景下省略>", "type": "TEE" }
}
```

```json
{
  "result": "REFRESHED",
  "deviceTicket": { "...": "新票据，剩余刷新次数 -1" }
}
```

### 3.3 设备注册（首次/换绑）

端点：`POST /v1/attest/register`

```json
{
  "deviceKeyHash": "sha256:9f2c...b1e0",
  "deviceCert": "<base64 DER 设备证书>",
  "accountRef": "acc_...",
  "deviceModel": "ANE-100",
  "claimedAtMs": 1737000000000
}
```

```json
{
  "result": "REGISTERED",
  "deviceId": "dev_01HZ...",           // 服务端内部 ID（不下发设备，防指纹）
  "registrationStatus": "active"
}
```

## 4. 证明校验流程（服务端内部）

```
收到 /v1/attest/verify
  → 1. 时间戳新鲜度检查（|now - timestampMs| ≤ 5min，防重放）
  → 2. nonce 检查（服务端签发的挑战 nonce，一次性）
  → 3. mTLS 客户端证书链校验（平台根 → 设备证书）
  → 4. 设备证书吊销检查（CRL / G2.2 实时吊销）
  → 5. quote 签名校验（TEE 厂商公钥 → AS 信任锚）
  → 6. quote 内容校验（PCR/声明与 deviceModel/osVersion 期望值比对）
  → 7. 设备注册表状态校验（registered/active，非吊销/注销）
  → 8. 签发设备票据（AS 私钥签名，scope/TTL 服务端裁决）
  → 9. 审计摘要落链
```

> **失败语义**：任一环节失败 → 返回对应错误码；`CERT_REVOKED` 时联动 G2.2 吊销事件（设备需重新注册或走恢复流程）。

## 5. 安全边界

- **信任锚分层**：平台根 CA（密钥方案 §1.1 平台密钥，HSM 保护）→ 设备证书 → TEE 厂商证书；任何一层验签失败即拒。
- **防重放**：nonce 一次性 + timestamp 新鲜度窗口 5 分钟；票据含 issuedAt/expiresAt。
- **最小暴露**：`deviceKeyHash` 为身份主键；服务端内部 `deviceId` 不下发设备。
- **降级口径**：`attestation.type=software` 仅允许最低档能力（如只读/审计），不允许 TIER_CLOUD 推理（对齐 A9.1 实现：TEE 可用时 attestationType=1 才放行云端）；`hardware` 最高信任。
- **证明强度分级**：

| attestationType | 信任级别 | 允许能力 |
|---|---|---|
| hardware（StrongBox/自研 TEE） | HIGH | 全部云端推理 + realtime |
| TEE（Keystore attestation） | MEDIUM | 云端推理 + transcribe |
| software | LOW | 仅诊断/审计上报，拒绝 TIER_CLOUD 推理 |

- **密钥保护**：AS 票据签名私钥存 HSM（对齐密钥方案 §3.3）；设备证书签发私钥（平台密钥）HSM 保护。
- **审计**：证明请求/结果全审计（含失败尝试，G5.1 票据滥用检测输入）。

## 6. 部署形态

```
设备 ──mTLS──► LB ──► AttestationService (无状态, 多副本)
                        │  ├─ 设备注册表（PostgreSQL/分布式 KV）
                        │  ├─ CRL/吊销缓存（订阅 G2.2 事件流）
                        │  ├─ nonce 缓存（Redis，一次性）
                        │  └─ HSM（票据签名）
                        ▼
                 CloudBroker (G1.1) —— 校验票据（离线验签，公钥内置于 Broker）
```

- **离线验签**：Broker 持有 AS 公钥，票据验签可离线完成（不回调 AS），支持 Broker 无状态水平扩容。
- **高可用**：AS 多副本 + 分布式 nonce 存储；AS 故障时 Broker 仍可校验未过期票据（fail-open 仅对有效票据），新会话暂缓。
- **地域**：按 G3.2 地域部署，设备就近接入。

## 7. 与端侧联动

| 端侧 | 联动点 |
|---|---|
| `IAgentInferenceRouter.attestDevice()` | 生成 `AttestationReport`（attestationType/quote/signature/timestampMs/nonce/deviceKeyHash/status）→ 映射到 `/v1/attest/verify` 请求 |
| `CloudGateway`（A9.2） | 会话握手首包携带证明；缓存/刷新设备票据（短时效） |
| `IAgentInferenceRouter.getCapabilities()` | 证明强度分级（hardware/TEE/software）影响可用档位（software 禁云端） |
| 端侧域名白名单 | 设备只连白名单 AS/Broker 域名（证书固定 + 白名单，D13 §4） |
| `STATUS_ATTESTATION_FAILED` | 端侧收到证明失败 → 触发重新证明一次；失败则拒绝出网（D13 §3） |
| 密钥方案 | 设备证书由平台根签发（对齐密钥方案 §2）；TEE 内持有设备私钥（E2.2 评审输入） |

## 8. 验收口径

- [ ] quote 校验通过后签发设备票据；票据短时效（≤5 分钟）、带 AS 签名、scope 限定
- [ ] 证明+握手全链路开销 P95 ≤ 100ms（R9.10）
- [ ] 失败路径错误码明确：`QUOTE_INVALID` / `CERT_REVOKED` / `DEVICE_UNREGISTERED` / `NONCE_STALE` / `SIGNATURE_INVALID`
- [ ] nonce 一次性 + 时间戳 5 分钟窗口生效（防重放）
- [ ] `software` 级证明拒绝 TIER_CLOUD 推理
- [ ] 设备证书吊销（G2.2 联动）实时生效（≤1 分钟，R9.9）
- [ ] Broker 离线验签设备票据通过（不回调 AS）
- [ ] 证明请求/结果全审计（G5.1 可查）
- [ ] H3.4 e2e：证明→Broker 链路通过

## 9. 遗留项

1. **证明频率权衡**：每次会话 vs 周期证明（D13 §8 开放问题 1）：v1 按"会话首包证明 + 票据刷新降频"，刷新时的降频校验（本地 PCR 短证明）需与 E2.2 评审结论对齐。
2. **OEM TEE 适配清单**：StrongBox/高通 QSEE/联发科 TEE 的 quote 格式差异需实测适配（D13 §8 开放问题 1）。
3. **设备换绑/转卖流程**：设备注销后重新注册的流程与旧票据吊销（G2.2）联动待定。
4. **证明强度与档位映射**：software/TEE/hardware 与模型档位（G1.2）的详细映射表需冻结。
5. **跨供应商证明链**：多 Broker 供应商时的证明链信任传递（D13 §8 开放问题 4）待评估。
