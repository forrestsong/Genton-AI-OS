# H5.1 KPI 遥测框架

> 任务编号：H5.1（质量工程部 · KPI 遥测框架）
> 里程碑：A1–A5（**A1 起持续运行**）· 前置：H1.1 · 依赖草案：D9 §0
> 状态：✅ 可执行交付（`tools/telemetry/kpi_telemetry.py` + 本说明）

## 1. 目的

建立 D9 KPI 的端到端遥测：**埋点 SDK → 上报管道 → 仪表盘 JSON → 达标门**。
自 A1 起持续运行，为 A5 建档提供历史基线，避免"缺历史基线"（WBS H 提示）。

## 2. 埋点 SDK 接口（KpiSdk）

| 方法 | 签名 | 说明 |
|---|---|---|
| `track` | `track(path: str, latency_ms: float)` | 记录一次延迟测量（毫秒） |
| `record` | `record(path: str, value: float)` | 记录非延迟指标（成功率/功耗等） |
| `mark` | `mark(event: str, **attrs)` | 记录里程碑/服务事件 |
| `snapshot` | `snapshot() -> dict` | 聚合当前样本（P50/P95/P99 + count） |
| `evaluate_gate` | `evaluate_gate(snap) -> dict` | 达标门判定（P95 vs D9 预算） |
| `write_dashboard` | `write_dashboard(milestone) -> path` | 仪表盘 JSON 落盘 |
| `persist_append` | `persist_append() -> path` | 增量原始流（ndjson） |

### 埋点接入点（A1 起逐步接入）

| 服务 | 埋点 path |
|---|---|
| 执行层/表单 | `command_to_visible`, `form_submit_visible` |
| 会话管理 | `session.switch.hot`, `session.switch.cold` |
| 感知层 | `ui.tree.incremental`, `ui.tree.snapshot`, `vlm.capture_perception` |
| 本体层 | `ontology.query`, `context.pack` |
| 唤醒 | `wake.intent_first` |
| MotionHub | `motion.shake_ready`, `motion.flip_record` |
| CallGate | `callgate.decision` |
| 决策模型 | `decision_model.inference` |
| 宏回归 | `macro.success_rate`（record） |
| 功耗建档 | `daily_power_added_pct`, `standby_power_added_pct`（record） |

## 3. 上报管道

```
各服务(KpiSdk.track/record)
        │
        ▼
进程内聚合（内存 + 样本列表）
        │
        ▼
snapshot() → P50/P95/P99
        │
        ▼
write_dashboard() → reports/quality/<milestone>/dashboard.json
persist_append()  → reports/quality/telemetry-raw.ndjson（增量趋势）
        │
        ▼
evaluate_gate() → PASS/FAIL（D9 预算表，P95 判定）
```

- 延迟类：P95 ≤ 预算 = PASS（D9 §0 表）；
- 非延迟类：`macro.success_rate ≥99%`、`daily_power_added_pct <0.5%`、
  `standby_power_added_pct <0.2%`（对齐 A5 门禁与 H4.3）；
- 未测量项：标记 `not_measured`（不判 FAIL，但计入覆盖缺口，需闭环）。

## 4. 仪表盘 JSON 格式

`reports/quality/<milestone>/dashboard.json`：

```json
{
  "milestone": "A2",
  "generated_at": "2026-XX-XXT00:00:00Z",
  "gate": {"pass": true, "fail_list": [], "not_measured": ["decision_model.inference"]},
  "kpis": {
    "command_to_visible": {"status": "pass", "p95_ms": 87.2, "target_p95": 100.0, "delta_ms": -12.8}
  },
  "raw_stats": {
    "command_to_visible": {"count": 120, "p50_ms": 61.4, "p95_ms": 87.2, "p99_ms": 94.1}
  },
  "meta": [{"event": "sdk_online", "ts": 1759..., "service": "form"}]
}
```

## 5. 运行方式

```bash
# 演示（注入合成样本，输出仪表盘 + 达标门）
python3 tools/telemetry/kpi_telemetry.py --demo --milestone A2

# 生成里程碑快照（读取已有样本）
python3 tools/telemetry/kpi_telemetry.py --snapshot A2

# 退出码：0=全部达标；1=存在未达标；2=用法错误
```

## 6. A1 起持续运行计划

| 里程碑 | 遥测动作 | 交付 |
|---|---|---|
| A1 | SDK 上线 + 埋点基线（策略/执行/表单桩） | `reports/quality/A1/dashboard.json` |
| A2 | 接入感知/会话/表单真机埋点 | `A2/dashboard.json` + 黄金样例门禁 |
| A3 | 接入本体/决策模型/端云 | `A3/dashboard.json` |
| A4 | 接入 MotionHub/CallGate/宏回归 | `A4/dashboard.json` |
| A5 | 全量 + 功耗差分合并 | `A5/dashboard.json` + H4.2/H4.3 报告 |

> 持续运行载体：系统服务（SystemUI/各 Manager 服务）内嵌 `KpiSdk.track`，
> 由守护进程定时 `write_dashboard`；CI 门禁（H1.1 流水线）Step 5 挂
> `kpi_telemetry.py --snapshot <milestone>` 作质量门。
