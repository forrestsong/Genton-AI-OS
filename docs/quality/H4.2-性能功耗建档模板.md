# H4.2 性能/功耗建档模板

> 任务编号：H4.2（质量工程部 · 性能/功耗建档）
> 里程碑：A5 · 前置：H4.1 · 依赖草案：D9
> 状态：📋 建档模板（每里程碑快照回填）

## 1. 目的

每个里程碑（A1–A5）生成一份**性能/功耗建档快照**，覆盖：命令可见延迟、
热/冷切换、功耗温度、帧率、预算超限记录。供 H5.1 达标门、H4.3 S7 功耗
差分与发布门禁取数。

> 建档原则：同一机型、同一测量脚本、同一环境基线（见 H4.1 §2.3），
> 保证跨里程碑可比。数据由 `tools/telemetry/kpi_telemetry.py` 采集
> 落盘，本模板定义呈现格式。

## 2. 建档目录结构

```
reports/quality/
└── A<里程碑>/
    ├── manifest.json            # 快照元数据（时间/机型/构建号/环境）
    ├── kpi-summary.json         # KPI 汇总（P50/P95/P99 + 门禁判定）
    ├── matrix-CPDAY10.json      # 每机型原始样本（可选，保留原始数据）
    ├── power-thermal.json       # 功耗/温度采样
    ├── frame-stats.json         # 帧率统计（帧时间/丢帧）
    ├── budget-overruns.json     # 预算超限记录
    └── H4.2-性能功耗建档-A<里程碑>.md   # 本模板渲染结果
```

## 5. 功耗/温度采样（power-thermal.json）

```json
{
  "device": "CPDAY10",
  "scenario": "idle_screen_off | idle_screen_on | camera_ready_idle | macro_heavy",
  "duration_s": 3600,
  "avg_current_ma": null,
  "avg_power_mw": null,
  "max_power_mw": null,
  "temp_min_c": null, "temp_max_c": null, "temp_avg_c": null,
  "daily_added_pct_vs_baseline": null,
  "method": "monsoon | bq25601 | pmic_readout"
}
```

> 场景定义：
> - `idle_screen_off`：息屏待机（无线网连接，无用户交互）；
> - `idle_screen_on`：亮屏待机 200nit；
> - `camera_ready_idle`：相机就绪后空转（对齐 H4.3 §4 的 15–30s 上限验证）；
> - `macro_heavy`：宏高频任务负载。

## 7. 预算超限记录（budget-overruns.json）

```json
[
  {
    "id": "OVR-001",
    "milestone": "A2",
    "device": "CPDAY10",
    "kpi": "command_to_visible",
    "target_p95_ms": 100,
    "measured_p95_ms": 132,
    "samples": 60,
    "suspected": "首帧渲染等待 DMI 桥",
    "defect_id": "AN-1234",
    "resolved": false
  }
]
```

> 门禁口径：任一 KPI P95 超预算 → 记超限并联动缺陷单；超限在下一
> 里程碑快照必须闭合（重新测量 ≤ 预算）。

1. 每里程碑由 `kpi_telemetry.py --snapshot A<里程碑>` 采集并落盘
