## 0. 结论摘要

数据最小化评审结论为 **有条件通过**。方案在「源头掩码 → 上下文索引 → 出端最小字段 → viewerRole 脱敏读 → 出网脱敏中间件」五层最小化链路上方向正确，与 E3.1 掩码基准、D8/D4/D13 契约一致。存在 4 项强制落地项：

1. **F1（源头掩码）**：`TOP_UI_SUMMARY` 必须由 UiTree 掩码层（而非上下文服务）在源头完成 PII 掩码；命中 E3.1 敏感类别（金融/健康/账号）**100% 掩码**，命中失败回退全屏掩码（R7.3）。上下文服务不得缓存未掩码节点原文。
2. **F2（出端最小字段）**：出网请求字段白名单冻结（联动 E2.3 §2.2），`contextDelta` 只含增量 + 脱敏摘要，禁止整包上下文出端。
3. **F3（viewerRole 脱敏读）**：审计/记忆/本体的**读取侧必须按 `viewerRole` 强制脱敏**——`USER` 只读脱敏摘要级、`ADMIN_BRAIN` 读 agentId/证据引用（对齐 D4 `AuditQuery.viewerRole`）；脱敏在服务端执行，客户端不可绕过。
4. **F4（出网脱敏中间件）**：G1.3 出端脱敏中间件必须**强制启用**（非可选开关），对所有 TIER_CLOUD 出网流量执行「PII 扫描剥离 + 字段白名单 + 摘要化」，中间件自身不进日志、不落审计正文。

**评审底线**：任何一层脱敏失败都必须**回退到更保守形态**（全屏掩码/拒绝出网/拒绝读取），禁止「脱敏失败但照常传递」——这是 R7.3/R7.9 的红线语义。

## 2. 评审正文

### 2.1 TOP_UI_SUMMARY 源头掩码

**评审结论：有条件通过（F1）**

- **现状**：D8 定义 `topUiSummary` 为「前台 UI 的语义摘要文本（小模型压缩，屏蔽密码/键盘/安全窗口区）」；D1 UiTree 服务掩码层产出。D8 开放问题 1（摘要由谁生成）待裁决。
- **评审裁决（关闭 D8 开放问题 1）**：
  - **掩码在 UiTree 掩码层完成**（感知侧，A2.1），上下文服务只消费「已掩码摘要」，**不缓存未掩码节点原文**——「存摘要」而非「存节点再按需摘要」（token/延迟最优且最小化留存面）。
  - 掩码强度执行 E3.1 §6.1 分级：金融/健康/账号三类**强/中掩码**（`6222 **** **** 7890` / `138****5678`）；密码/CVV/私钥**全掩码**。
  - **回退路径（R7.3）**：小模型掩码失败/超时 → 回退规则库（E3.1 §3.4，≥70% 保底）→ 再失败 → **全屏掩码/返回空**（`topUiSummary=""` 且标记安全窗口在屏）。
  - **验收**：对齐 E3.1 评估集（3.5 节）——`TOP_UI_SUMMARY` 命中率 ≥90%（总体）、金融 ≥95%、健康 ≥92%、账号 ≥88%、金融/健康/账号子类别 100% 覆盖。
- **红线对齐**：R7.1（源头掩码）、R7.4（掩码率 90%）、R7.5（敏感类别 100%）、R7.2（安全窗口内容不进上下文索引——`topUiSummary=""` 时上下文不得索引）。

### 2.2 出端最小字段

**评审结论：通过（F2 冻结）**

- **现状**：D13 已定义 `ContextRef`（packId/kvSession/delta）替代整包 prompt、`EgressPlan.fieldsToSend` 字段清单、`privacyMode` 声明。E2.3 已冻结字段白名单。
- **评审裁决**：
  - 出端字段 = **E2.3 §2.2 白名单**（deviceKeyHash/contextDelta/privacyMode/budget/sessionRef），其他字段一律拒绝；
  - `contextDelta.deltaFields` 只允许**增量字段**，禁止整包上下文上传；
  - 摘要化：出端内容在允许范围内必须为脱敏摘要（如通知 → `NotificationDigest.summaryMasked`，只给 count + 来源 + 摘要，D8）。
- **联动**：G1.3 中间件（F4）是出端最小字段的**执行保证**——路由层的字段白名单声明与中间件的实际剥离必须对账（防止「声明白名单但实际整包上传」）。

### 2.3 viewerRole 脱敏读

**评审结论：有条件通过（F3）**

- **现状**：D4 `AuditQuery.viewerRole`（0=USER 脱敏摘要 / 1=ADMIN_BRAIN 含 agentId/证据引用）；D6 本体 `VisibilityRule` 授权过滤；D4 记忆 `query()` 返回「调用方有权读取的掩码后呈现版本」。
- **评审裁决**：
  - **服务端强制脱敏**：`viewerRole=USER` 的查询结果在服务端剥除敏感字段（`summary` 保留、`payloadHash`/`evidenceRefs`/`agentId` 按角色裁剪），**客户端传入的脱敏请求参数不可信**——必须以服务端角色判定为准（调用方权限 + 令牌 scope）。
  - **角色映射**：
    - `USER`（隐私仪表盘/用户本人）：脱敏摘要级；
    - `ADMIN_BRAIN`（系统大脑，`trusted_assistant`）：agentId/证据引用，但**不含明文 secret**（R4.2 只记 `hasValue`）；
    - 第三方 Agent：**不可读审计链**（R10.9 沙箱不得访问系统签名权限）。
  - **记忆读取**：`IAgentMemoryService.query` 按「调用方 agentId + 令牌 `memory.read` + 用户授权」返回掩码版本；`LONG_TERM` 跨 Agent 共享需显式授权（D4 §2.1）。
- **验收**：用例「USER 角色查询审计 → 断言响应不含 evidenceRefs/agentId」「第三方 Agent 查询审计 → STATUS_DENIED」。

### 2.4 出网脱敏中间件要求（G1.3 需求基线）

**评审结论：有条件通过（F4）**

- **强制启用**（R7.9）：脱敏中间件是 TIER_CLOUD 出网的**必经环节**，非可选开关。任何出网请求不经过中间件即 `STATUS_DENIED`（路由层强校验）。
- **中间件功能基线**：
  1. **PII 扫描剥离**：对出网负载执行 E3.1 掩码模型 + 规则库（命中敏感类别剥离或替换）；
  2. **字段白名单**：剥离后字段集合必须 ⊆ E2.3 白名单，多余字段丢弃（或拒绝整包）；
  3. **摘要化**：长正文压缩为脱敏摘要（对齐 `summaryMasked` 口径）；
  4. **策略联动**：`privacyMode` 声明与实测脱敏状态一致，不一致 → 拒（D13 §4 违反即拒）。
- **中间件自身安全**：
  - 中间件日志不得记录明文负载（R4.5）；
  - 中间件处理记录进 `EgressPlan` 审计摘要（字段清单 + 脱敏状态），不落正文（D13 §3）；
  - 中间件在云侧（G 部实现），端侧由 `preflightEgress` 做同口径声明——**端云两侧脱敏口径必须一致并对账**（防「端侧说脱敏了、云侧收到明文」）。

### 2.5 最小化与其他面的联动

- **与 R9.3 出网字段白名单**：F2 与 E2.3 字段白名单同一事实源。
- **与 R7.10 云端删除传播**：最小化 + 删除传播双保险——即使最小化失败导致数据出端，云端删除传播（E3.3）兜底。
- **与 S5-h 捕获降采样**：视觉问答帧出端前同样过脱敏中间件（D9 §8.1 视觉问答走既有帧捕获/掩码/出端策略）。

## 4. 验收口径

- [ ] `TOP_UI_SUMMARY` 掩码率 ≥90%、金融 ≥95%、健康 ≥92%、账号 ≥88%、敏感子类别 100%（E3.1 评估集）。
- [ ] 安全窗口在屏时 `topUiSummary=""` 且上下文不索引（R7.2）。
- [ ] 出端字段违反白名单 → `STATUS_DENIED`；`contextDelta` 只含增量。
- [ ] `viewerRole=USER` 审计查询不含 `evidenceRefs`/`agentId`；三方 Agent 查询审计被拒。
- [ ] 绕过中间件的出网请求被拒；端云脱敏口径对账一致。
- [ ] 脱敏失败回退路径生效（全屏掩码/拒绝出网/拒绝读取）。

## 5. 遗留项

1. **掩码后文本可读性量化**：E3.1 §7.2 已列为开放问题，需人因测试（H5.2）补「脱敏可读性」指标。
2. **跨模态 PII（图片中的卡号）**：OCR + 掩码在 A4 期评估（E3.1 §7.2）。
3. **动态敏感词更新**：规则库 OTA（C6.4）后中间件与端侧掩码规则同步更新。
4. **最小化指标的遥测**：建议在隐私仪表盘显示「出网字段数/脱敏状态」的日统计（对齐 D13 透明）。
