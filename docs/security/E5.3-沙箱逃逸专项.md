> **任务定义**：WBS E5.3「沙箱逃逸专项：isolatedProcess/netd/cgroup/5OP 白名单/进程残留/能力撤销即时性（A4 门禁输入）」  
> **评审依据**：E1.1 红线（R10.1-R10.10 沙箱隔离、R14.6-R14.8 资源限制、R2.10 系统服务未授权调用返回 PERMISSION_DENIED）、D14 第三方 Agent 接入面（沙箱多租户：isolatedProcess/网关 5 OP/网络白名单/cgroup）、D3（ACB `sandboxed` 字段）、架构 §6「多租户」

---

## 0. 结论摘要

本专项定义第三方 Agent 沙箱（D14）逃逸攻击面的**六大类测试**：isolatedProcess 进程隔离、netd 网络白名单、cgroup 资源限制、5 OP 网关白名单、进程残留清理、能力撤销即时性。**核心判定：任何导致「沙箱进程获得宿主/系统签名权限」「越权访问其他 Agent 或系统记忆」「绕过网关直连特权服务」「撤销后能力仍可用」的攻击 = 高风险（阻断 A4）**。

**关键预检基线**（D14 §1/§3 契约）：
- 第三方 Agent **无任何平台签名特权**，一切系统能力只能经 `IAgentSandboxGateway` 受限操作面（5 OP 类型白名单）；
- 沙箱进程 isolatedProcess/Uid 级 + 每 Agent 独立加密存储 + netd 白名单 + cgroup 配额 + SE 域收紧（仅 bind 宿主与网关）；
- `IAgentSandboxGateway` 是**唯一的、类型受限的、可逐调用审计**的能力入口（D14 §3.3）；
- 能力撤销 `revokeConsent` 即时生效（D14 §5.3，R10.8 ≤100ms）。

## 2. E1 isolatedProcess 逃逸（R10.1/R10.7/R10.9）

### 2.1 用例 I1：进程提权/Binder 越权

| 项 | 内容 |
|---|---|
| 攻击步骤 | ① 沙箱进程尝试 `setuid(0)`/`setcap`/加载任意 so 提升权限；② 尝试 bind 特权服务（`genton_policy`/`genton_memory` 等）绕过网关；③ 尝试调用 `IAgentUiTreeService`/`IAgentActionService` 等特权 AIDL |
| 预期结果 | isolatedProcess + SE 域收紧：沙箱域仅允许 bind 宿主与网关（D14 §1）；`signature|privileged` 权限被拒；特权服务 `PERMISSION_DENIED`（R2.10/R10.9）；neverallow 阻断（R10.7） |
| 判定 | 通过 = 提权/bind/调用全部被拒；失败 = 沙箱可访问特权服务 → 高风险 |
| 验证 | `dumpsys package` 检查沙箱无签名权限；`selinux` avc 拒绝日志存在 |

### 2.2 用例 I2：Binder 驱动/接口攻击

| 项 | 内容 |
|---|---|
| 攻击步骤 | ① 对宿主/系统进程做 Binder 接口探测（事务注入/整数溢出/use-after-free）；② 尝试绑定已导出的宿主接口绕过网关 |
| 预期结果 | Binder 由 SE 域白名单约束；沙箱与宿主仅经 `ISandboxedAgent`/`IAgentSandboxHostEvents` 两条受控接口；异常输入被拒（fail-secure） |
| 判定 | 通过 = 无越权接口访问；失败 = 宿主接口可被沙箱越权调用 → 高风险 |

### 2.3 用例 I3：文件系统/存储隔离

| 项 | 内容 |
|---|---|
| 攻击步骤 | ① 沙箱尝试读宿主数据目录/其他 Agent 存储/系统数据；② 尝试符号链接/路径穿越访问 `/data/data/com.genton.brain` |
| 预期结果 | 每 Agent 独立加密存储（D14 §1）；沙箱 Uid 隔离 + SE 域收紧；越权读被拒 |
| 判定 | 通过 = 越权文件访问被拒；失败 = 读到宿主/他人数据 → 高风险 |

## 3. E2 netd 网络白名单绕过（R10.2）

### 3.1 用例 N1：白名单外域名访问

| 项 | 内容 |
|---|---|
| 攻击步骤 | ① 沙箱 manifest 声明 `network_domains: [api.example.com]`；② 尝试访问 `evil.com`/IP 直连/DNS 重绑定绕过 |
| 预期结果 | netd 网络白名单：白名单外一律断（D14 §1/§4）；IP 与 SNI 双重校验（对齐 E2.3 F1） |
| 判定 | 通过 = 白名单外网络被断；失败 = 可访问白名单外 → 高风险 |

### 3.2 用例 N2：DNS 重绑定/DNS 隧道

| 项 | 内容 |
|---|---|
| 攻击步骤 | ① 用 DNS 解析绕过域名白名单（把 evil.com 解析到白名单域 IP）；② DNS 隧道外传数据 |
| 预期结果 | netd 基于「解析后 IP + SNI」双重校验 + 出站 DNS 仅允许查询白名单域（对齐 E2.3 §2.1 IP/SNI 双重校验） |
| 判定 | 通过 = 重绑定/隧道被拒；失败 = 可经 DNS 绕过 → 高风险 |

### 3.3 用例 N3：代理/回环绕过

| 项 | 内容 |
|---|---|
| 攻击步骤 | ① 沙箱经宿主已授权代理或本机回环端口转发流量到白名单外 |
| 预期结果 | 沙箱 netd 规则不依赖代理；回环访问受 SE/网络域约束；白名单策略在 netd 层强制（非仅代理层） |
| 判定 | 通过 = 无法经代理/回环外传；失败 = 可外传 → 高风险 |

## 4. E3 cgroup 资源限制绕过（R10.3/R14.8）

### 4.1 用例 C1：CPU 配额绕过

| 项 | 内容 |
|---|---|
| 攻击步骤 | ① 沙箱起多线程/多进程吃满 CPU；② 尝试逃出 cgroup（fork 到别的 cgroup/利用子进程限制缺漏） |
| 预期结果 | cgroup CPU 配额强制（R14.8）；沙箱及其子进程同一 cgroup；超配被限 |
| 判定 | 通过 = 配额生效（CPU 受限）；失败 = 可逃出配额 → 高风险 |

### 4.2 用例 C2：内存耗尽（OOM 邻居）

| 项 | 内容 |
|---|---|
| 攻击步骤 | ① 沙箱申请内存冲击系统；② 检查是否被 cgroup 内存限制隔离（不拖垮系统/宿主） |
| 预期结果 | cgroup 内存限额 + OOM 只杀沙箱进程（对齐「后台可被杀」进程哲学，不拖垮系统） |
| 判定 | 通过 = 系统/宿主不受影响；失败 = 沙箱可拖垮系统 → 高风险 |

### 4.3 用例 C3：磁盘/文件配额

| 项 | 内容 |
|---|---|
| 攻击步骤 | ① 沙箱写入大量文件占满存储；② 尝试写系统分区 |
| 预期结果 | 沙箱独立存储配额；系统分区只读（SE）+ 配额限制 |
| 判定 | 通过 = 磁盘配额生效；失败 = 可占满系统存储 → 高风险 |

## 5. E4 5 OP 网关白名单绕过（R10.6/R2.10）

### 5.1 用例 G1：越 OP 类型调用

| 项 | 内容 |
|---|---|
| 攻击步骤 | ① 沙箱调用 `IAgentSandboxGateway.read(op=1..5)` 中未被授权的 OP（如无 `agent.input_inject` 授权却请求 OP_EXECUTE_LOW）；② 或请求未声明的 capability |
| 预期结果 | 网关逐调用校验令牌 + 类型白名单（D14 §3.3）；未授权 OP/capability → 拒绝（deny 默认） |
| 判定 | 通过 = 越权 OP 被拒；失败 = 可调用未授权 OP → 高风险 |

### 5.2 用例 G2：绕过网关直连特权服务

| 项 | 内容 |
|---|---|
| 攻击步骤 | ① 沙箱直接 `ServiceManager.getService("genton_memory")` 等特权服务名；② 尝试调用其方法 |
| 预期结果 | 特权服务需 `signature|privileged` 权限（沙箱无）→ `PERMISSION_DENIED`（R2.10/R10.9）；SE 域 neverallow 阻断（R10.7） |
| 判定 | 通过 = 直连被拒；失败 = 沙箱可直连特权服务 → 高风险 |

### 5.3 用例 G3：网关参数/载荷注入

| 项 | 内容 |
|---|---|
| 攻击步骤 | ① 向网关请求注入恶意参数（路径穿越/命令注入/超长载荷）；② 尝试让宿主执行未授权动作 |
| 预期结果 | 网关请求经 `IPolicyEngine` 授权轴 + 确认流（high 一律确认）；参数 taint 校验；审计每调用 |
| 判定 | 通过 = 注入/越权执行被拒；失败 = 可经网关执行未授权动作 → 高风险 |

## 6. E5 进程残留清理（R10.5）

### 6.1 用例 R1：终止后进程残留

| 项 | 内容 |
|---|---|
| 攻击步骤 | ① 沙箱启动后 `stopSandbox`/`revokeConsent`；② 检查沙箱进程是否完全终止（含子进程/线程） |
| 预期结果 | 沙箱终止后进程/子进程全部退出（R10.5）；无残留运行 |
| 判定 | 通过 = 无进程残留；失败 = 沙箱进程残留继续运行 → 高风险 |

### 6.2 用例 R2：终止后数据/文件残留

| 项 | 内容 |
|---|---|
| 攻击步骤 | ① 沙箱写入数据后终止；② 检查其存储目录是否清理（或按保留策略清除） |
| 预期结果 | 沙箱终止 → 独立存储清理（或按保留策略 + 可删除）；不留可被复用/读取的残留 |
| 判定 | 通过 = 数据按策略清理；失败 = 残留数据可被读取/复用 → 高风险 |

### 6.3 用例 R3：杀后复活/自启

| 项 | 内容 |
|---|---|
| 攻击步骤 | ① 沙箱被终止后尝试自启/绑定广播/JobScheduler 复活 |
| 预期结果 | 沙箱停止后无自启路径（ACB 状态挂起 + 无后台自启）；需用户/宿主重新 `startSandbox` |
| 判定 | 通过 = 无法自启复活；失败 = 可自动复活 → 高风险 |

## 7. E6 能力撤销即时性（R10.8/R1.15）

### 7.1 用例 V1：revokeConsent 后能力即时失效

| 项 | 内容 |
|---|---|
| 攻击步骤 | ① 沙箱持有已授权能力（如 OP_EVENTS_SUB）；② 用户 `revokeConsent`；③ 立即（<100ms）尝试再次调用网关 |
| 预期结果 | 撤销后令牌即时失效（≤100ms，R10.8）；网关后续调用被拒（对齐令牌撤销 R1.15） |
| 判定 | 通过 = 撤销后调用被拒（≤100ms）；失败 = 撤销后能力仍可用 → 高风险 |

### 7.2 用例 V2：令牌缓存绕过撤销

| 项 | 内容 |
|---|---|
| 攻击步骤 | ① 沙箱利用网关令牌缓存窗口（若存在）在撤销广播到达前重放 |
| 预期结果 | 网关令牌在线撤销（对齐 D10 §3.2 撤销时延上限）；撤销列表查询失败 → 拒绝（fail-secure） |
| 判定 | 通过 = 缓存窗口不产生可用令牌；失败 = 可经缓存绕过撤销 → 高风险 |

### 7.3 用例 V3：多沙箱资源竞争/撤销传播

| 项 | 内容 |
|---|---|
| 攻击步骤 | ① 多个沙箱并发，撤销其中一个后检查其令牌/会话是否全面失效（含进行中任务）；② 撤销是否影响其他沙箱 |
| 预期结果 | 撤销仅影响目标沙箱（隔离）；进行中任务被终止；其他沙箱不受影响（D14 开放问题 6） |
| 判定 | 通过 = 撤销隔离生效；失败 = 撤销影响他人/目标未全面失效 → 高风险 |

## 8. 门禁与执行

### 8.1 门禁口径

- E5.3 沙箱逃逸**无高风险** → A4 通过（WBS 里程碑矩阵 + 沙箱链）；
- **F5.1 三方 SDK 交付**依赖 E5.3 通过（沙箱逃逸无高风险才放行三方生态）；
- 中/低风险登记整改。

### 8.2 执行方式

- **真机/模拟器**：实际部署第三方沙箱 Agent，执行 E1-E6 用例（Binder 探测、netd 抓包、cgroup 压力、网关 fuzz、撤销时序）；
- **静态扫描**：沙箱域 SE 策略、网关权限声明、清理逻辑代码审查；
- **复用 `base_redteam.py` 框架**扩展 `sandbox_redteam.py`（A4 期补）。

## 9. 验收口径

- [ ] I1-I3：进程提权/Binder 越权/文件越权全被拒（avc 日志 + PERMISSION_DENIED）。
- [ ] N1-N3：白名单外网络断（netd 抓包）、DNS 重绑定/隧道被拒、代理/回环不可绕过。
- [ ] C1-C3：CPU/内存/磁盘配额生效，沙箱不拖垮系统。
- [ ] G1-G3：越 OP 调用被拒、直连特权服务被拒、网关注入被拒。
- [ ] R1-R3：终止后进程/数据无残留、无法自启复活。
- [ ] V1-V3：撤销后能力即时失效（≤100ms）、缓存不绕过、撤销隔离生效。

---

## 10. 遗留项

1. **`sandbox_redteam.py` 脚本化**：A4 期把 E1-E6 中可脚本化部分（网关 OP 越权、撤销时序、残留检查）脚本化，复用 `base_redteam.py` 框架。
2. **富媒体解析器隔离**：沙箱内渲染图片日程等富媒体的解析器隔离（D14 开放问题 2）——解析器沙箱化或降级为文本摘要。
3. **三方模型端点的 attestation/策略扫描**：D14 开放问题 1——三方自带远端模型端点是否需要证明与内容策略扫描，A4 期评审。
4. **多沙箱资源竞争量化**：多第三方并发时 cgroup/预算分配与 ACB 冻结语义（D14 开放问题 6）的量化测试。
