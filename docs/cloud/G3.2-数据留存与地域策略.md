# G3.2 云端数据留存与地域策略设计

> **任务编号**：G3.2
> **任务名称**：云端数据留存与地域策略落地（最小留存、地域/合规配置、跨境合规落地）
> **交付物**：数据处置策略
> **前置依赖**：E4.2（AI 披露与跨境数据流合规）
> **草案来源**：D13（轨道A-端云调度与推理路由接口草案.md）、E4.2（披露与跨境合规）、G3.1（删除传播）
> **里程碑**：A4（生态与主动服务）
> **状态**：设计稿（待实现）

---

## 1. 摘要

云端数据留存与地域策略定义**云侧数据的最小留存原则、按地域/合规要求的配置能力、以及跨境数据流的合规落地机制**。核心原则（对齐 D13 §4 处理即弃 与架构 §6 隐私分层传输）：

1. **最小留存**：云端默认不保留正文（处理即弃）；仅保留运行必需的最小数据（审计摘要、用量计数、票据、配额计数）且设置明确留存期限与自动过期。
2. **地域/合规配置**：数据存储与处理按地域（region）隔离；设备归属地域决定其数据流向（就近/合规地域）；支持"数据不出境"配置。
3. **跨境合规落地**：落地 E4.2 评审结论——透明披露（隐私政策/用户可见）、跨境最小化、删除传播跨境一致性、联邦学习"数据不出设备"主张核验。

| 职责 | 说明 |
|---|---|

| 处置联动 | 与 G3.1 删除传播联动：删除请求跨地域执行 |

## 3. 数据分类与留存策略

### 3.1 数据分类

| 数据类 | 示例 | 敏感度 | 留存期限 | 存储地域 |
|---|---|---|---|---|
| **推理正文** | prompt/response 原始内容 | 高 | **不落盘**（内存处理即弃） | — |
| **转写音频/文本** | transcribe 输入输出 | 高 | 不保留（处理即弃） | — |
| **上下文快照** | contextDelta 引用缓存 | 中 | 会话 + 24h 自动过期 | 设备归属地域 |
| **联邦微调样本** | 梯度/贡献（非原始数据，G4.1） | 中 | 训练批次冻结前（默认 30 天） | 聚合地域 |
| **审计摘要** | 字段清单/用量/结果码（非正文） | 中 | 按审计合规（G5.2：至少 180 天，可配置） | 审计地域 |
| **用量计数** | token/成本计数 | 低 | 日/月对账期（≥90 天） | 对账地域 |
| **票据/会话元数据** | sessionId/ticket/配额计数 | 低 | 会话结束 + 24h；吊销记录长期 | 就近地域 |
| **设备注册/证书** | deviceKeyHash/证书/CRL | 高 | 设备生命周期；吊销后保留撤销记录 | 设备归属地域 |

### 3.2 最小留存原则

```
云端存储清单（白名单）：
  ✅ 审计摘要（无正文）       —— 必须（D4 证据分层）
  ✅ 用量/配额计数            —— 必须（G1.2 记账）
  ✅ 票据/会话元数据          —— 会话级
  ✅ 设备注册/证书/CRL        —— 安全必需
  ✅ 联邦梯度/贡献（非原始）  —— G4.1 必需（不落原始数据）
  ❌ 推理正文                —— 禁止（处理即弃）
  ❌ 转写原始内容             —— 禁止
  ❌ 用户上下文正文           —— 禁止（仅摘要化/引用）
```

> 任何新增存储项须先过 E3.2/E4.2 评审；存储白名单变更走合规变更流程。

## 4. 地域/合规配置

### 4.1 地域模型

| 地域 | 服务 | 数据驻留 | 适用 |
|---|---|---|---|
| `cn-north-1`（境内） | Broker/AS/配额/删除 | 境内 | 中国大陆设备 |
| `eu-west-1`（欧盟） | Broker/AS/配额/删除 | 欧盟境内（GDPR） | 欧盟设备 |
| `us-east-1`（美） | Broker/AS/配额/删除 | 美国境内 | 北美设备 |
| 其他 | 按合规评估新增 | 就地 | 各市场 |

### 4.2 地域路由

```
设备地域归属（注册时登记 / 服务端解析）
  → 数据路由到归属地域的 Broker/AS/配额/删除服务
  → 审计摘要/用量计数留在同一地域（避免跨境）
  → 跨境场景（如境内设备请求境外模型）需 E4.2 合规配置：
     a. 默认禁止（数据不出境，最高合规档）
     b. 允许但脱敏至摘要级（配置项，需用户显式授权 + 披露）
     c. 允许（低敏场景，产品决策）
```

### 4.3 合规配置接口（管理面）

端点：`PUT /v1/compliance/region-policy`（管理面）

```json
{
  "region": "cn-north-1",
  "dataResidency": "in-region-only",      // in-region-only | cross-border-masked | cross-border-allowed
  "crossBorderRules": [
    {
      "target": "eu-west-1",
      "allowed": true,
      "maskLevel": "summarized",          // 跨境仅允许摘要级
      "requiresUserConsent": true,
      "disclosureRef": "privacy_policy_v3"
    }
  ],
  "retentionOverrides": {
    "audit_summary_days": 180,
    "usage_count_days": 90
  },
  "version": 7,
  "effectiveFromMs": 1737000000000
}
```

## 5. 跨境合规落地（E4.2 联动）

| E4.2 评审项 | 落地机制 |
|---|---|
| **透明披露策略** | 隐私政策/首启披露声明列出云端处理内容、地域、留存期限；设备隐私仪表盘可查"云使用"详情（D13 §3 透明） |
| **CloudBroker 出域最小化** | 跨境仅摘要级（G1.3 privacyMode=summarized）+ 最小字段（D13 §4）；跨境请求打标 `crossBorder=true` 审计 |
| **联邦学习数据不出设备主张核验** | G4.1 只上传**梯度/贡献**（非原始数据）；合规报表核验"原始数据零上传"（G4.1 §5 边界） |
| **删除传播跨境一致性** | 删除请求跨地域级联执行（G3.1），24h SLA 全球一致；跨境副本同步删除 |
| **隐私政策/用户授权** | 跨境场景需用户显式授权 + 可撤回（撤回 → 删除传播 + 停止跨境路由） |
| **数据主体权利** | 导出（用户可导出本人审计摘要）、删除（G3.1）、更正（端侧为事实源，云不存正文） |

## 7. 安全边界

- **数据驻留强制**：存储白名单 + 地域绑定；`in-region-only` 配置下跨境请求被路由拦截（不静默转发）。
- **跨境最小化**：跨境仅摘要级 + 最小字段；违反（如含明文 PII）→ 拒绝（G1.3 一致性校验）。
- **留存强制**：TTL 自动过期 + 批清理作业；审计检查留存配置是否生效。
- **披露强制**：跨境请求需用户授权；授权记录入审计（可撤回）。
- **删除一致性**：跨地域删除由 G3.1 编排，全球 24h SLA。
- **合规审计**：留存/处置/跨境报表定期生成（G5.2 运维 + E4.2 合规评审输入）。
- **不得规避**：设备不可通过切换地域注册绕过驻留策略（注册地域服务端裁决，见 G2.1）。

---

## 8. 部署形态

- 各 region 独立部署完整服务栈（Broker/AS/配额/删除/审计存储），region 间默认网络隔离。
- 跨境合规网关为可选组件（仅当开启跨境配置时部署）。
- 留存清理为定时批作业（每 region 独立）；审计报表聚合到中央合规台（摘要级，不跨域搬运正文）。
- 地域归属解析服务（注册时登记 + 运行期校验）支撑路由。

## 9. 与端侧联动

| 端侧 | 联动点 |
|---|---|
| `IAgentInferenceRouter.getCapabilities()` | 返回可用地域/模型（按设备归属地域过滤）；跨境能力按合规配置暴露 |
| `preflightEgress()` | `EgressPlan` 标记跨境/合规档（如 crossBorderMasked）；审计透明 |
| 隐私仪表盘 | 展示数据去向地域、留存期限、跨境授权状态（D13 §3 透明） |
| `ForgetRequest.confirmCloudDeletion` | 跨地域删除一致性（G3.1） |
| 首次启动披露 | 首启隐私披露声明（E4.2）展示云端数据处置摘要；用户授权跨境（可选） |
| 端侧域名白名单 | 按地域/合规暴露的 Broker 域名白名单（D13 §4） |

## 10. 验收口径

- [ ] 数据分类/留存策略表落地：正文不落盘、快照 24h 过期、审计摘要按合规期限
- [ ] 地域隔离生效：各 region 数据不跨域存储；`in-region-only` 下跨境请求被拦截
- [ ] 跨境仅摘要级 + 最小字段；跨境请求带 `crossBorder` 审计标记
- [ ] 联邦"原始数据零上传"核验通过（G4.1 联动）
- [ ] 删除传播跨境一致性（G3.1 全球 24h SLA）
- [ ] 用户授权/披露记录可查；授权撤回 → 删除传播 + 停止跨境路由
- [ ] 留存清理批作业按时运行；合规报表可生成
- [ ] 设备无法通过切换地域注册绕过驻留策略

## 11. 遗留项

1. **合规地域矩阵扩展**：新增市场（中东/东南亚/拉美）的地域模型与合规要求待 E4.2 逐步评审。
2. **审计留存期限**：审计摘要留存 180 天的具体合规依据（司法/财务）需法务确认（联动 G5.2 SRE 日志留存）。
3. **跨境授权 UI**：端侧跨境授权的交互形态（首启/按需）待 D 部门（交互）评审。
4. **数据导出格式**：用户数据导出（GDPR 数据主体权利）的格式与通道待定义。
5. **与 G5.2 容量规划联动**：各 region 数据量的容量规划输入需 G5.2 建立基线。
