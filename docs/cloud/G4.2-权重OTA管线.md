# G4.2 端侧模型/值集权重 OTA 管线设计

> **任务编号**：G4.2
> **任务名称**：端侧模型/值集权重 OTA 管线（签名校验、灰度、回滚，与 C6.4 值集 OTA 联动）
> **交付物**：权重 OTA 管线
> **前置依赖**：G4.1（联邦微调聚合服务）、H1.1（CI 基建）
> **草案来源**：D13（轨道A-端云调度与推理路由接口草案.md §6 模型更新）、D17（策略 DSL）、C6.4（值域知识库 OTA 更新协议，docs/value_domain_ota_protocol.md）、密钥管理与签名方案.md
> **里程碑**：A5（体验学习与加固）
> **状态**：设计稿（待实现）

---

## 1. 摘要

端侧模型/值集权重 OTA 管线负责把**联邦微调（G4.1）产出的模型权重**与**值域知识库更新（C6.4）**安全分发到设备端，遵循与系统 OTA/可信启动同款的信任模型：

1. **签名校验**：所有权重/值集包必须带 OTA 密钥签名（密钥方案 §2.5/§4.5），设备端校验通过才落地；不信任未签名权重（D13 §6）。
2. **灰度**：分批灰度（1% → 5% → 10% → 50% → 100%，对齐 C6.4 §7），按机型/地域/通道分组，可暂停。
3. **回滚**：失败/回归自动或半自动回滚到上一可用版本；回滚版本同样签名校验。
4. **与 C6.4 值集 OTA 联动**：模型权重更新前先校验值域兼容性（分类器 ↔ 值域版本绑定，C6.4 §4.2）；值集更新失败不阻塞模型旧版运行。

---

## 2. 职责

| 职责 | 说明 |
|---|---|
| 权重工件管理 | 接收 G4.1 聚合权重 / 值集包（C6.4），登记版本、哈希、签名 |
| 签名发布 | 用 OTA 密钥签名权重包/值集包（HSM），生成发布清单 |
| 灰度调度 | 按批次/机型/地域/通道灰度；可暂停/加速/回滚 |
| 设备端交付 | 设备出网检查更新 → 拉取包 → 端侧校验签名/哈希/兼容性 → 落地 |
| 回滚编排 | 失败回滚（自动，错误率阈值触发）+ 手动回滚（管理面）；端侧回滚同签名校验 |
| 遥测与门禁 | 收集安装成功率/错误率/回滚率（对齐 C6.4 §8 阈值：成功率 >98%、总耗时 P95 <10s、回滚率 <1%） |
| C6.4 联动 | 模型权重 ↔ 值域版本兼容性检查；值集更新触发 PolicyEngine 重载（C6.4 §6） |

## 4. 签名与校验链（对齐密钥方案）

```
发布端：
  G4.1 聚合权重 / C6.4 值集包
    → sha256 计算 → OTA 私钥签名（HSM, 密钥方案 §2.5：RSA 4096 / 25 年）
    → 打包（权重 .signed.bin = 权重 + .sig + .sha256；值集 zip 同 C6.4 §3）

设备端（可信启动同款校验，D13 §6）：
  1. 下载包 → 校验 sha256（完整性）
  2. 校验 OTA 签名（验签失败 → 拒绝安装，FAILED_SIGNATURE）
  3. 兼容性校验（模型 ↔ 值域版本 ↔ 策略引擎版本，C6.4 §4）
  4. 备份当前版本（回滚目标）
  5. 落地 → 校验模型可加载（加载自检）
  6. 遥测回传 → 灰度门禁评估
```

> 签名密钥与系统 OTA 同源但分离（密钥方案 §1.1 密钥分离原则）；权重 OTA 不信任未签名权重（D13 §6）。

## 5. 灰度策略（对齐 C6.4 §7 + 扩展）

| 批次 | 范围 | 通过条件 | 超时 |
|---|---|---|---|
| batch-1 | 内部测试设备（1%） | 安装成功率 >98%，无回归 | 24h |
| batch-2 | Beta 用户（5%） | 错误率 <5%，回滚率 <2% | 48h |
| batch-3 | 早期采用者（10%） | 错误率 <5% | 72h |
| batch-4 | 主流用户（50%） | 错误率 <5%，无投诉激增 | 7 天 |
| batch-5 | 全部（100%） | 全量放行 | — |

**暂停条件**（任一触发即暂停该批次）：错误率 >5%、回滚率 >2%、用户投诉激增、严重 Bug（对齐 C6.4 §7.2）。
**自动回滚条件**：错误率 >10%、系统崩溃率上升、数据完整性问题（C6.4 §7.3）。

## 6. 与 C6.4 值集 OTA 联动

| 场景 | 联动逻辑 |
|---|---|
| 模型权重先到，值域未更新 | 模型加载前查 `compatibleValueDomain`；不兼容 → 阻止模型加载并告警（C6.4 §2.1） |
| 值集先到，模型未更新 | ValueDomainVersionManager 更新值域 → 通知 PolicyEngine 重载（C6.4 §2.2/§6） |
| 策略规则引用未知 category | DSL 编译器查询 ValueDomainVersionManager → 本地值域过时 → 触发值集 OTA（C6.4 §2.3） |
| 回滚 | 模型回滚到旧版时检查旧版与当前值域兼容；值集回滚同 C6.4 §6.3（备份恢复） |
| 失败 | 任一更新失败保留当前版本不变（C6.4 §6.2），上报遥测，可选通知用户 |

> **编排权**：G4.2 管"模型权重"，C6.4 管"值域知识库"；两者通过"版本兼容性检查"耦合（C6.4 §4.2），G4.2 在发布清单中声明兼容约束，端侧 ValueDomainVersionManager 执行检查。

## 8. 安全边界

- **签名强制**：权重/值集/清单全部 OTA 签名；设备端验签失败拒绝安装（不信任未签名权重）。
- **完整性**：sha256 校验；下载损坏拒绝（FAILED_CHECKSUM）。
- **防降级攻击**：版本号单调递增检查（C6.4 §4.1）；降级仅限显式回滚。
- **通道隔离**：stable/beta/dev 通道不可跨通道更新（C6.4 §4.4）；用户可手动切换。
- **兼容性强制**：模型 ↔ 值域 ↔ 策略引擎版本不兼容 → 拒绝安装（C6.4 §4.2/§4.3）。
- **回滚安全**：回滚包同样签名校验；回滚记录审计。
- **灰度隔离**：按批次控制爆炸半径；恶意包无法通过签名与哈希校验。
- **审计**：发布/安装/回滚全审计（G5.1 → A5.3）；遥测上报脱敏（不含用户数据）。

## 9. 部署形态

- OTA 服务（无状态，管理面 + 设备面接口）+ 工件对象存储（CDN 加速）。
- 签名在 HSM（OTA 密钥，密钥方案 §2.5）。
- 灰度状态/版本注册表（PostgreSQL + 缓存）。
- 遥测聚合（对齐 C6.4 §8 指标：成功率/延迟/回滚率）→ G5.1 审计台/G5.2 监控。
- 端侧安装器：随系统镜像内置（可信启动同款校验器），由 `IAgentAssetLibraryService`（D11 资产 OTA 通道）协同。
