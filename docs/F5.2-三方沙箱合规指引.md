## 1. 合规总则（三条红线，来自 D14）

| # | 红线 | 落地点 |
|---|---|---|
| ① | 第三方 Agent **无任何平台签名特权**，一切系统能力只能经沙箱网关受限操作面 | isolatedProcess + 5 OP 白名单 + SELinux neverallow（B6.1） |
| ② | **deny 默认**：能力逐项授权、会话级 TTL、随时一键撤销 | 首启授权向导 + consentStore + revokeConsent（B6.1） |
| ③ | 沙箱 Agent 的每条动作仍过策略引擎（含确认），**系统不信任其自带模型输出** | GatewayConsumer → IPolicyEngine（B6.2） |

本指引围绕这三条红线，给出**授权 UI 交互走查**（§2）、**能力撤销演示**（§3）、
**deny 默认提醒**（§4）与**审计透明**（§5）四部分，供联调与评审使用。

## 2. 授权 UI 交互走查（首启向导）

### 2.1 场景

用户首次启动一个第三方 Agent（以 `sample-agent` "便签小助手"为例）。

### 2.2 走查步骤

| 步骤 | UI 元素 | 交互 | 校验点 |
|---|---|---|---|
| S1 | 清单能力列表 | 展示 Agent 名称、开发者、版本、每项能力的 `purpose` 与 `risk` 档位 | ① 列表与 `requested_capabilities` 完全一致；② 无隐藏能力 |
| S2 | 逐项授权开关 | 每项能力一个开关，**默认全部关闭**（deny 默认） | 默认 OFF；用户必须主动开启 |
| S3 | 风险提示 | high 能力额外红色警示 + 说明（"每次使用需确认"） | 文案如实；不得弱化 |
| S4 | 出网与预算披露 | 展示 `network_domains` 与 `budgets` | 用户可知出网范围与成本上限 |
| S5 | 确认提交 | "允许" / "拒绝" | 拒绝则 Agent 不启动（部分拒绝=仅授权勾选项） |
| S6 | 授权落库 | 授权记录落策略引擎（`USER_ALLOW_TASK` 同级持久条目） | 可在策略视图（D4.3）复查 |

### 2.3 验收标准（走查通过条件）

- [x] 未授权能力在 UI 中默认关闭，用户不操作则一项都不开（deny 默认）；
- [x] 授权记录持久化且可撤（见 §3）；
- [x] 用户可拒绝其中任意一项，其余照常工作（逐项授权，非全有全无）；
- [x] UI 展示的信息与清单声明一致（无夸大/隐藏）。

> 走查脚本参考：人工按 S1–S6 走一遍即可；自动化断言可对齐 H3.3 沙箱网关端到端
> （5 OP 白名单、逐调用令牌/审计、一键撤销即时生效、deny 默认）。

## 3. 能力撤销演示（Revocation）

### 3.1 触发路径

1. **隐私仪表盘**（D4.x）→ "该 Agent 最近做过什么" → "停止该 Agent / 撤销授权"；
2. **策略视图**（D4.3）→ Agent 授权清单 → 一键停止授权；
3. **设置页** → 三方 Agent 管理 → 撤销。

以上均收敛到 `IAgentSandboxManager.revokeConsent(handle)`。

### 3.2 撤销后的即时效果（可演示的验收项）

| 时序 | 行为 | 验收标准 |
|---|---|---|
| T0 撤销瞬间 | consentStore 内存缓存清空该 Agent 全部已授权能力 | ≤100ms（B6.1 R10.8） |
| T0+ | 该 Agent 任何受保护网关调用 → `STATUS_DENIED` | 返回码正确，不留后门 |
| T0+ | 沙箱停止（stop(reason=REVOKED)） | 进程终止、资源回收、残留清理（B6.1 R10.5） |
| T0+ | 审计记录撤销事件（agentId + 时间 + 原因） | 隐私仪表盘可见"已撤销"时间线 |
| T0++ | 若 Agent 仍尝试调用 | 网关返回 DENIED + 审计记录尝试，**不静默放行** |

### 3.3 演示脚本（联调用）

```
1. 启动 Agent 并授权 UI_READ_MASKED + MEMORY_OWN
2. 正常调用 2 次（记录审计）
3. 用户在仪表盘一键撤销
4. 再调用网关 read(OP_UI_READ_MASKED) → 预期返回 STATUS_DENIED
5. 查看审计：撤销事件 + 被拒调用均可见
6. 重新授权需走完整首启向导（不可静默恢复）
```

### 3.4 合规要点

- 撤销**不可被 Agent 绕过**（Agent 无权限操作 consentStore）；
- 撤销后 Agent 不应重试已撤销操作（`stop(REVOKED)` 语义）；
- 部分撤销（只关某项能力）与全量撤销（revokeConsent）都支持。

## 4. deny 默认（Deny-by-Default）提醒

### 4.1 系统侧（联调时逐条核对）

- [x] 未授权能力 → 网关 `STATUS_DENIED`（不因"曾经授权过"放行，TTL 过期即失效）；
- [x] 未在白名单的 OP 类型 → 拒绝（`isOpTypeValid`，B6.1）；
- [x] 未在白名单的出网域名 → iptables 阻断（默认 deny UID 全量出网，B6.1）；
- [x] 策略引擎对 sandboxed 来源：更严格基线，high 一律确认（B6.2）；
- [x] 沙箱进程无任何系统签名权限（isolatedProcess 无共享权限，B6.1 R10.9）。

### 4.2 开发者侧（写清单时对照）

1. **不申请就不给**：只列 `requested_capabilities` 中真正需要的能力；
2. **不声明就不通**：任何出网域必须列入 `network_domains`；模型域与业务域分开声明；
3. **不授权就不动**：未获授权的能力即使代码里调用了，也会被网关拒绝 —— 请做好 `STATUS_DENIED` 的错误处理，而不是重试轰炸；
4. **事件订阅收窄**：`events.read` 带 `types`，禁止通配。

> 提醒：deny 默认不仅是系统机制，也是**你的 Agent 的预期行为** —— 用户可能部分拒绝授权，
> 你的 Agent 必须能在"只有部分能力"下优雅降级（如无 UI_READ 时改为询问用户）。

## 5. 审计透明（Audit Transparency）

### 5.1 审计覆盖（每次网关调用）

| 审计字段 | 说明 |
|---|---|
| category | `AUDIT_CAT_SANDBOX` |
| agentId | 三方 Agent 身份（你的 `sandbox_agent.id`） |
| opType | 5 OP 之一 |
| requestId / timestamp | 请求追踪与时间 |
| result | 成功 / 拒绝 / 确认 / 超限 |
| policyDecision | ALLOW / DENY / CONFIRM（B6.2） |

### 5.2 用户可见（隐私仪表盘）

- "该 Agent 最近做过什么"：按时间线的意图→动作→证据（viewerRole=USER 脱敏视图）；
- 能力撤销历史与时间点；
- 预算/配额使用情况（日成本、调用次数）。

### 5.3 开发者可见

- 你的 Agent 只能查询**与自己相关**的活动摘要（D14 权限矩阵：审计域"可看与自己相关，不可读他人/证据导出"）；
- 完整的逐调用审计由系统留存（A5.2 哈希链），你的 Agent 不接触。

### 5.4 合规要点

- 审计不可被三方篡改（哈希链 + TEE 周期锚定，A5.2/E2.2）；
- 审计展示字段脱敏（PII 掩码，viewerRole 脱敏读）；
- 你应在 `purpose` 中如实描述用途 —— 审计时间线是用户信任你的依据，虚报会导致撤销与下架。

## 6. 联调失败排查对照（结合 sample-agent）

| 现象 | 根因 | 处理 |
|---|---|---|
| `startSandbox` 返回 `STATUS_UNSIGNED` | signature_ref 未替换为真实指纹 | 替换并重签 |
| 授权向导不展示某项能力 | 能力名未命中策略引擎清单 | 与 B 部门核对能力名（D14 能力名以系统为准） |
| 模型调用超时/被拒 | 模型域名不在 `network_domains` | 补域名并 `version++` 重新授权 |
| 网关返回 `STATUS_DENIED` 且审计有记录 | 用户撤销或 TTL 过期 | 重新授权；Agent 侧优雅降级 |
| 一切调用返回 error | 重放/联调环境缺宿主服务 | 先确认 B6.1 沙箱宿主已部署 |
