## 1. 设计目标

实现 SystemUI 持有的 **Assistant Surface** 与 **Launcher3** 在同一"首页容器"上的呈现优先级切换，满足：

1. **切换性能**：模式切换 <1 帧（目标 <16ms）
2. **任务保活**：切换时 Agent 任务保持后台运行，不丢会话状态
3. **视角切换**：切换的是"视角"而非"进程"，避免 Home Activity 重建
4. **统一容器**：Assistant Surface 和 Launcher 表面共享同一容器，优先级动态切换

## 2. 架构设计

### 2.1 核心概念

```
┌─────────────────── SystemUI 进程 ───────────────────┐
│                                                      │
│  ┌────────────── DualModeContainer ──────────────┐  │
│  │                                                │  │
│  │  [Assistant Surface]  (SystemUI 系统窗口)      │  │
│  │       ▲                                        │  │
│  │       │ 优先级切换                              │  │
│  │       ▼                                        │  │
│  │  [Launcher3 Bridge]   (传统桌面入口)           │  │
│  │                                                │  │
│  └────────────────────────────────────────────────┘  │
│                                                      │
│  ModeStateMachine:                                   │
│    - ASSISTANT_MODE (默认)                          │
│    - STANDARD_MODE                                  │
│    - TRANSITION (切换中)                            │
│                                                      │
└──────────────────────────────────────────────────────┘
```

**关键设计决策**：

- **不使用 Activity 切换**：避免 `startActivity(Launcher)` 和 `startActivity(Assistant)` 的传统模式，因为会触发 Activity 生命周期重建（onCreate → onStart → onResume），延迟 >100ms
- **使用窗口可见性切换**：Assistant Surface 和 Launcher Bridge 都是持久化窗口，通过 `WindowManager` 的可见性（visibility）和 Z-order 切换
- **状态源统一**：UI 状态全部来自 ACB 服务（`IAgentRuntimeService.getAgentStatus`），不在 UI 层缓存

### 2.2 模式状态机

```kotlin
enum class SystemMode {
    ASSISTANT_MODE,    // AI 全能助理模式（默认）
    STANDARD_MODE,     // 普通应用模式
    TRANSITION         // 切换中（<16ms）
}

// 状态转换
ASSISTANT_MODE ──┬──> TRANSITION ──> STANDARD_MODE
                 │                         │
                 └─────────<───────────────┘
                  (通过悬浮球/侧边栏/QS Tile)
```

**状态转换规则**：

| 当前状态 | 触发事件 | 目标状态 | 副作用 |
|---------|---------|---------|--------|
| ASSISTANT_MODE | 用户点击"去桌面" | TRANSITION → STANDARD_MODE | Assistant Surface 降级为悬浮球，Launcher 升至前台 |
| STANDARD_MODE | 用户点击悬浮球/侧边栏/QS Tile | TRANSITION → ASSISTANT_MODE | 悬浮球消失，Assistant Surface 升至前台 |
| TRANSITION | 动画完成 | ASSISTANT_MODE / STANDARD_MODE | 状态稳定 |

### 2.3 关键组件

#### 2.3.1 DualModeContainer

```kotlin
/**
 * 双模式容器：持有 Assistant Surface 和 Launcher Bridge，管理优先级切换
 * 
 * 职责：
 * - 持有两个表面的窗口引用
 * - 管理 Z-order 和可见性
 * - 协调切换动画（<16ms 目标）
 * - 保证切换期间不销毁任何窗口
 */
class DualModeContainer(
    private val context: Context,
    private val windowManager: WindowManager
) {
    private var assistantSurface: AssistantSurfaceWindow? = null
    private var launcherBridge: LauncherBridgeWindow? = null
    private var currentMode: SystemMode = SystemMode.ASSISTANT_MODE
    
    fun switchMode(targetMode: SystemMode, animationDurationMs: Long = 150L)
    fun getCurrentMode(): SystemMode
    fun getAssistantSurface(): AssistantSurfaceWindow?
    fun getLauncherBridge(): LauncherBridgeWindow?
}
```

#### 2.3.2 ModeStateMachine

```kotlin
/**
 * 模式状态机：管理模式转换逻辑
 * 
 * 职责：
 * - 验证状态转换合法性
 * - 触发状态变更回调
 * - 处理异常状态（如切换超时）
 */
class ModeStateMachine {
    private var currentState: SystemMode = SystemMode.ASSISTANT_MODE
    private val listeners = mutableListOf<ModeStateListener>()
    
    fun requestTransition(targetMode: SystemMode): Boolean
    fun onTransitionComplete()
    fun onTransitionFailed(reason: String)
    fun addListener(listener: ModeStateListener)
}

interface ModeStateListener {
    fun onModeChanged(oldMode: SystemMode, newMode: SystemMode)
    fun onTransitionStarted(targetMode: SystemMode)
    fun onTransitionFailed(reason: String)
}
```

#### 2.3.3 AssistantSurfaceWindow

```kotlin
/**
 * Assistant Surface 窗口：SystemUI 系统窗口，承载助理界面
 * 
 * 特性：
 * - TYPE_SYSTEM_OVERLAY 窗口类型（高优先级）
 * - FLAG_SECURE（外部截图不可见）
 * - 可降级为悬浮球（最小化状态）
 */
class AssistantSurfaceWindow(
    private val context: Context,
    private val windowManager: WindowManager
) {
    private var windowView: View? = null
    private var isMinimized: Boolean = false
    
    fun show()
    fun hide()
    fun minimize()  // 降级为悬浮球
    fun restore()   // 从悬浮球恢复全屏
}
```

#### 2.3.4 LauncherBridgeWindow

```kotlin
/**
 * Launcher Bridge 窗口：连接传统 Launcher3 的桥接层
 * 
 * 职责：
 * - 管理 Launcher3 的可见性

 * - 保持 Launcher 进程常驻（避免冷启动）
 */
class LauncherBridgeWindow(
    private val context: Context,
    private val windowManager: WindowManager,
    private val launcherIntent: Intent
) {
    fun show()
    fun hide()
    fun ensureLauncherAlive()  // 保活 Launcher 进程
}
```

## 3. 切换性能优化策略（<1 帧目标）

### 3.1 预加载策略

```kotlin
/**
 * 预加载策略：启动时初始化所有窗口，避免切换时创建
 */
class PreloadStrategy {
    fun preloadOnBoot() {
        // 1. 创建 Assistant Surface 窗口（不可见）
        assistantSurface = AssistantSurfaceWindow(context, windowManager)
        
        // 2. 启动 Launcher3 进程并保持后台（不可见）
        launcherBridge = LauncherBridgeWindow(context, windowManager, launcherIntent)
        launcherBridge.ensureLauncherAlive()
        
        // 3. 默认显示 Assistant Surface
        assistantSurface.show()
    }
}
```

### 3.2 零拷贝切换

```kotlin
/**
 * 零拷贝切换：通过 WindowManager 的 Z-order 和可见性切换，避免内容重建
 */
fun DualModeContainer.switchMode(targetMode: SystemMode, animationDurationMs: Long) {
    when (targetMode) {
        SystemMode.STANDARD_MODE -> {
            // ASSISTANT → STANDARD
            // 1. Launcher 升至前台（Z-order 提升）
            windowManager.updateViewLayout(launcherBridge.windowView, layoutParamsTop)
            launcherBridge.show()
            
            // 2. Assistant Surface 降级为悬浮球（不销毁窗口）
            assistantSurface.minimize()
        }
        
        SystemMode.ASSISTANT_MODE -> {
            // STANDARD → ASSISTANT
            // 1. Assistant Surface 从悬浮球恢复全屏
            assistantSurface.restore()
            
            // 2. Launcher 降至后台（Z-order 降低，但不销毁）
            windowManager.updateViewLayout(launcherBridge.windowView, layoutParamsBottom)
            launcherBridge.hide()
        }
    }
    
    currentMode = targetMode
}
```

**性能分析**：

- `updateViewLayout`：~2-5ms（系统调用）
- `minimize/restore` 动画：~10ms（硬件加速）
- 总计：**~12-15ms < 16ms（1 帧）** ✅

### 3.3 动画优化

```kotlin
/**
 * 动画优化：使用硬件加速 + 预合成
 */
class TransitionAnimator {
    fun animateToStandard(duration: Long = 150L) {
        // 淡出 + 缩小到悬浮球
        assistantSurface.animate()
            .alpha(0f)
            .scaleX(0.1f)
            .scaleY(0.1f)
            .setDuration(duration)
            .withLayer()  // 硬件加速
            .start()
        
        // Launcher 淡入
        launcherBridge.animate()
            .alpha(1f)
            .setDuration(duration)
            .withLayer()
            .start()
    }
}
```

## 4. 任务保活机制

### 4.1 状态源设计

```kotlin
/**
 * 状态源：UI 不缓存任何业务状态，全部来自 ACB 服务
 */
class AssistantStateSource(
    private val runtimeService: IAgentRuntimeService
) {
    // 获取当前所有活跃任务
    fun getActiveTasks(): List<AgentTaskInfo> {
        return runtimeService.getAgentStatus()?.activeTasks ?: emptyList()
    }
    
    // 监听任务状态变化
    fun observeTaskChanges(callback: (AgentTaskInfo) -> Unit) {
        runtimeService.registerListener(object : IAgentRuntimeListener.Stub() {
            override fun onAgentStateChanged(status: AgentStatus) {
                status.activeTasks.forEach { callback(it) }
            }
        })
    }
}
```

### 4.2 切换时的任务可见性

```kotlin
/**
 * 任务可见性策略：
 * - ASSISTANT_MODE：任务卡片在会话流中显示
 * - STANDARD_MODE：任务状态在悬浮球中显示
 */
class TaskVisibilityManager(
    private val stateSource: AssistantStateSource
) {
    fun updateVisibility(mode: SystemMode) {
        when (mode) {
            SystemMode.ASSISTANT_MODE -> {
                // 显示完整任务卡片
                val tasks = stateSource.getActiveTasks()
                conversationView.showTaskCards(tasks)
            }
            
            SystemMode.STANDARD_MODE -> {
                // 悬浮球显示任务摘要
                val tasks = stateSource.getActiveTasks()
                floatingBubble.showTaskSummary(tasks.size, tasks.firstOrNull()?.name)
            }
        }
    }
}
```

## 5. 集成到 SystemUI

### 5.1 启动流程

```kotlin
/**
 * SystemUI 启动时初始化双模式容器
 */
class SystemUIApplication : Application() {
    override fun onCreate() {
        super.onCreate()
        
        // 1. 初始化 WindowManager
        val windowManager = getSystemService(WINDOW_SERVICE) as WindowManager
        
        // 2. 创建双模式容器
        val dualModeContainer = DualModeContainer(this, windowManager)
        
        // 3. 预加载所有窗口
        PreloadStrategy(dualModeContainer).preloadOnBoot()
        
        // 4. 默认显示 Assistant Mode
        dualModeContainer.switchMode(SystemMode.ASSISTANT_MODE, animationDurationMs = 0L)
    }
}
```

### 5.2 HOME 键拦截

```kotlin
/**
 * HOME 键拦截：根据当前模式路由到不同表面
 */
class HomeKeyInterceptor(
    private val dualModeContainer: DualModeContainer
) : PhoneWindowManager.HomeKeyHandler {
    
    override fun onHomeKey(event: KeyEvent): Boolean {
        when (dualModeContainer.getCurrentMode()) {
            SystemMode.ASSISTANT_MODE -> {
                // 已在助理模式，HOME 键无操作（或返回助理首页）
                return true
            }
            
            SystemMode.STANDARD_MODE -> {
                // 在普通模式，HOME 键切回 Launcher 首页（传统行为）
                return false  // 交由系统处理
            }
        }
    }
}
```

## 7. 性能指标与验收标准

| 指标 | 目标值 | 测量方法 |
|-----|--------|---------|
| 模式切换延迟（P95） | <16ms（1 帧） | Systrace 测量 `switchMode` 调用耗时 |
| 切换动画流畅度 | 60fps 不掉帧 | dumpsys SurfaceFlinger 观察帧率 |

## 8. 风险与缓解

### 8.1 风险识别

| 风险 | 影响 | 概率 | 缓解措施 |
|-----|-----|-----|---------|
| WindowManager Z-order 不稳定 | 切换失败 | 中 | 增加健康检查，检测 Z-order 错误并自动修复 |
| Launcher 进程被系统杀死 | 切换时需冷启动 Launcher（延迟 >200ms） | 高 | 将 Launcher 标记为 `PERSISTENT` 进程，提高 OOM 优先级 |
| Assistant Surface 内存泄漏 | 长期运行后内存溢出 | 中 | 定期 dump 内存，监控泄漏点 |
| 切换动画与系统动画冲突 | 动画卡顿 | 低 | 禁用系统默认 Activity 切换动画 |

### 8.2 降级策略

如果 <16ms 切换目标无法达成：

1. **降级到 <100ms**：允许完整动画（150ms）但保证流畅
2. **移除动画**：直接切换，无过渡效果
3. **回退到 Activity 模式**：使用传统 `startActivity` 但优化启动性能
