## 1. 背景与目标

### 1.1 问题陈述

现有 AI 操作系统延迟高的根本原因是**串行反应式架构**：
```
用户动作 → 感知(50-200ms) → LLM规划(300-2000ms) → UI自动化(300-1000ms) 
→ App冷启(300-1000ms) → 结果渲染(200ms+)
```

**核心思想**：在用户/Agent 动作发生**之前**预测下一步意图，驱动"预创建/预取/预订阅"，把感知链路成本从"事后串行"变成"事中命中"。

### 1.2 设计目标

| 指标 | 目标（P95） | 当前估算 |
|---|---|---|
| 本地唤醒→意图识别首响应 | <200ms | 300-600ms |
| 带DMI/宏的应用冷启动 | ≤800ms（含首帧） | 300-1000ms |
| 预测命中率 | ≥70% | - |
| 误预取率（浪费） | <2% | - |
| 模型推理延迟 | <20ms | - |

### 1.3 核心约束

- **数据不出设备**：RL 训练完全本地化，不上传原始数据
- **最小权限**：预测模型仅系统大脑可访问，第三方 Agent 不可见
- **可回收**：所有预创建进入"可回收池"，未命中即后台回收
- **敏感场景暂停**：支付/输入框聚焦/安全窗口强制暂停预测执行

```
│           ↑                                      ↑        │

└──────────────────────────────────────────────────────────┘
         ↑                                          ↓
    ┌─────────┐                              ┌──────────┐
    │EventStream│                            │ActionService│

    └─────────┘                              └──────────┘
```

### 2.2 核心组件

| 组件 | 职责 | 输入 | 输出 |
|---|---|---|---|
| **StateExtractor** | 提取状态特征向量 | 事件流、上下文、记忆 | State Vector (维度≈128) |
| **RLInferenceEngine** | RL 模型推理 | State Vector | Action + Confidence |
| **GateControl** | 置信度门控与敏感场景检测 | Action + Confidence + Context | 执行决策 (允许/拒绝) |
| **PrefetchExecutor** | 执行预取动作 | Action | 预创建/预取结果 |
| **RecyclePool** | 管理预创建生命周期 | 预创建资源 | 回收/命中统计 |
| **LocalTrainer** | 本地增量训练 | 状态-动作-奖励三元组 | 更新模型权重 |
| **RewardCalculator** | 计算奖励信号 | 预测动作 + 实际动作 | Reward Value |

## 3. 状态空间设计

### 3.1 状态特征定义（128维向量）

| 特征类别 | 维度 | 说明 | 来源 |
|---|---|---|---|
| **时间上下文** | 16 | 星期(7) + 小时(24) one-hot + 工作日/周末标志 | 系统时钟 |
| **位置上下文** | 8 | 粗位置语义：在家/办公/在途/其他 (one-hot) | 粗定位 + 记忆 |
| **前台应用** | 32 | 当前 App packageName 的 embedding | UI 树服务 |
| **UI 节点** | 16 | 最近交互节点的语义 embedding | UI 树服务 |
| **最近事件** | 24 | 最近 5 条事件的类型 embedding (通知/日历/消息) | 事件流 |
| **操作序列** | 24 | 最近 N 步用户操作 (tap/type/swipe) 或 Agent 动作 | 动作服务审计 |
| **当前实体** | 8 | 当前聊天对象/文档的实体 ID embedding | 本体服务 |

## 5. RL 模型设计

### 5.1 模型架构（超轻量策略网络）

```
输入: State Vector (128维)
    ↓
Embedding Layer (128 → 256)
    ↓
LSTM / GRU (256 → 128, 序列长度=5)  # 捕获操作序列
    ↓
Self-Attention (128 → 128)           # 关注关键特征
    ↓
MLP (128 → 64 → 32)
    ↓
输出层 (32 → 动作空间大小≈100)
    ↓
Softmax → (Action Probabilities, Value)
```

**参数量估算**：
- Embedding: 128×256 = 32K
- LSTM: 256×128×4 (gates) ≈ 131K
- Attention: 128×128×3 (Q/K/V) ≈ 49K
- MLP: 128×64 + 64×32 ≈ 10K
- Output: 32×100 ≈ 3K
- **总计**: ≈ **15-20M 参数** ✅（符合 ≤20M 约束）

### 5.2 训练策略

**算法**: Proximal Policy Optimization (PPO)
- **优势**: 样本效率高、稳定性好、适合边缘设备
- **超参数**:
  - Learning Rate: 3e-4
  - Batch Size: 32（小批量，低内存）
  - Clip Range: 0.2
  - Entropy Coefficient: 0.01（鼓励探索）
  - Discount Factor (γ): 0.99

### 5.3 奖励函数设计

```python
Reward = Match_Reward - Waste_Penalty

Match_Reward = {
    +10  if 预测动作与实际动作完全匹配
    +5   if 预测目标App正确但动作类型不同
    0    otherwise
}

Waste_Penalty = {
    -1   if 预创建未命中（浪费资源）
    -2   if 预创建导致内存压力（OOM风险）
    0    if 仅预取数据（成本低）
}

# 时间折扣：预测越早奖励越高
Time_Bonus = max(0, 1 - (t_actual - t_prediction) / 60s)

Final_Reward = (Match_Reward + Waste_Penalty) * (1 + Time_Bonus)
```

### 5.4 本地训练流程

```
1. 观察 (Observation)
   → 提取当前状态特征 S_t

2. 推理 (Inference)
   → RL模型预测动作 A_pred 和置信度 C

3. 执行 (Execution)
   → 门控判断后执行预取 (如果 C ≥ 阈值)

4. 等待实际动作 (Actual Action)
   → 用户/Agent 真实执行动作 A_actual

5. 计算奖励 (Reward)
   → R = Reward(A_pred, A_actual, 资源消耗)

6. 存储经验 (Experience Replay)
   → 保存 (S_t, A_pred, R, S_t+1) 到本地缓冲区

7. 周期训练 (Periodic Training)
   → 每积累 N 条经验（N=100）或每天凌晨训练一次
   → 使用 PPO 更新策略网络
   → 训练数据永不出设备
```

## 6. 门控机制

### 6.1 置信度分档执行

| 置信度区间 | 执行策略 | 允许动作类型 | 审计级别 |
|---|---|---|---|
| **HIGH (≥0.9)** | 允许预创建/预热 | 所有类型（白名单内） | 详细审计 |
| **MEDIUM (0.7-0.9)** | 仅预取数据/预订阅 | PREFETCH_DATA, PRESUBSCRIBE_UI | 简要审计 |
| **LOW (<0.7)** | 不执行 | - | 仅观察 |

### 6.2 敏感场景暂停

以下场景**强制暂停预测执行**（保留观察用于训练）：
- 支付页面在屏（检测支付关键字、SECURE FLAG）
- 输入框聚焦（键盘弹出状态）
- 安全窗口在屏（FLAG_SECURE）
- 通话进行中
- 电量 < 15%（省电模式）

```kotlin
fun isSensitiveContext(context: ContextFrame): Boolean {
    return context.isPaymentPage 
        || context.isInputFocused
        || context.hasSecureWindow
        || context.isInCall
        || context.batteryLevel < 15
}
```

### 6.3 预算控制

- **并发预创建上限**: ≤3 个 Activity 实例
- **内存预算**: 预创建池总内存 ≤200MB
- **CPU 时间片**: 预热进程限制在后台 CPU 组（≤5% CPU）
- **网络预算**: 预取数据限制 ≤10MB/分钟

## 7. 可回收预创建池

### 7.1 生命周期管理

```kotlin
class RecyclableResource(
    val resourceId: String,
    val type: PrefetchActionType,
    val targetApp: String,
    val createdAt: Long,
    val ttl: Long = 60_000L,  // 默认60秒过期
    var status: ResourceStatus = ResourceStatus.PENDING
)

enum class ResourceStatus {
    PENDING,    // 已创建，等待命中
    HIT,        // 已命中使用
    EXPIRED,    // 超时未命中
    RECYCLED    // 已回收
}

class RecyclePool {
    private val resources = ConcurrentHashMap<String, RecyclableResource>()
    
    // 创建预取资源
    fun create(resource: RecyclableResource) {
        resources[resource.resourceId] = resource
        scheduleRecycle(resource)
    }
    
    // 命中资源
    fun hit(resourceId: String): Boolean {
        val resource = resources[resourceId] ?: return false
        if (resource.status == ResourceStatus.PENDING) {
            resource.status = ResourceStatus.HIT
            return true
        }
        return false
    }
    
    // 定期回收
    private fun scheduleRecycle(resource: RecyclableResource) {
        handler.postDelayed({
            if (resource.status == ResourceStatus.PENDING) {
                recycle(resource)
            }
        }, resource.ttl)
    }
    
    private fun recycle(resource: RecyclableResource) {
        resource.status = ResourceStatus.RECYCLED
        // 回收逻辑：销毁 Activity、释放内存
        when (resource.type) {
            PRECREATE_ACTIVITY -> destroyActivity(resource.targetApp)
            PREWARM_APP -> killBackgroundProcess(resource.targetApp)
            PREFETCH_DATA -> clearCache(resource.resourceId)
            else -> {}
        }
        resources.remove(resource.resourceId)
    }
}
```

### 7.2 命中统计

```kotlin
data class PredictionMetrics(
    val totalPredictions: Int,
    val hits: Int,              // 命中次数
    val misses: Int,            // 未命中次数
    val falsePositives: Int,    // 误预取（浪费）
    val avgConfidence: Float,
    val avgLatencyReduction: Long // 平均延迟降低 (ms)
) {
    val hitRate: Float get() = hits.toFloat() / totalPredictions
    val wasteRate: Float get() = falsePositives.toFloat() / totalPredictions
}
```

## 10. 隐私与安全

### 10.1 隐私保护

- ✅ **数据不出设备**：所有训练数据、模型权重仅本地存储
- ✅ **最小权限**：预测模型仅系统大脑可访问，第三方 Agent 无权读取
- ✅ **用户透明**：仪表盘提供"行为预测学习"开关与最近预测展示
- ✅ **可撤销**：用户可一键关闭预测功能，清除历史数据

### 10.2 安全边界

- ✅ **敏感场景暂停**：支付/输入/安全窗口强制禁用预测执行
- ✅ **白名单约束**：预创建仅限白名单 App，防止预取恶意 App
- ✅ **审计完整**：所有预测动作、命中/浪费统计进入审计链
- ✅ **预算限制**：内存/CPU/网络预算硬上限，防止资源滥用

## 12. 风险与缓解

### 12.1 技术风险

| 风险 | 影响 | 缓解措施 |
|---|---|---|
| 模型收敛慢 | 命中率达标延迟 | 预训练+迁移学习、冷启动使用规则策略 |
| 误预取率高 | 资源浪费、用户体验差 | 严格门控（≥0.9才预创建）、快速回收 |
| 内存压力 | OOM、系统卡顿 | 硬预算限制（≤200MB）、LRU 回收 |
| 功耗超标 | 续航下降 | NPU 小核推理、批处理、深夜训练 |

### 12.2 产品风险

| 风险 | 影响 | 缓解措施 |
|---|---|---|
| 隐私担忧 | 用户抵触"被预测" | 默认关闭、透明展示、可撤销 |
| 误预取打扰 | 意外启动 App | 白名单限制、无 UI 打扰、静默回收 |
| 学习效果差 | 无明显体验提升 | 灰度验证、A/B 测试、迭代优化 |
