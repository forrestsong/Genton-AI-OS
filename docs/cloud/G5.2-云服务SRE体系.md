# G5.2 云服务 SRE 体系设计

> **任务编号**：G5.2
> **任务名称**：云服务 SRE 体系（SLA、日志留存、事故复盘、容量规划）
> **交付物**：运维体系
> **前置依赖**：G5.1（出网审计台与异常检测）
> **草案来源**：D13（轨道A-端云调度与推理路由接口草案.md）、G1.1-G4.2（云服务）、H5.1（KPI 遥测框架）
> **里程碑**：A5（体验学习与加固）
> **状态**：设计稿（待实现）

---

## 1. 摘要

云服务 SRE 体系为全部云侧服务（G1.1-G5.1）定义**可度量的可靠性基线**：

1. **SLA**：各服务可用性/延迟/删除传播等 SLA 目标、测量方式、违约补偿。
2. **日志留存**：运行日志/审计日志/遥测的分级留存策略（对齐 G3.2 数据分类），支撑排障与合规。
3. **事故复盘**：事故分级、响应流程（SRE 值班）、复盘（blameless postmortem）、改进闭环。
4. **容量规划**：按设备规模/用量增长建模的容量规划流程，保障 SLA 的资源配置。

## 3. SLA 定义

### 3.1 服务 SLA 表

| 服务 | SLI | SLO（月度） | 备注 |
|---|---|---|---|
| CloudBroker 网关（G1.1） | 可用性 / P95 首 token 延迟 | 99.9% / P95 <800ms | 端侧断线降级兜底（D13 §6） |
| 路由配额（G1.2） | 配额检查可用性 | 99.95% | 故障 fail-open（配额） |
| 脱敏中间件（G1.3） | 可用性 / 处理延迟 | 99.9% / P95 <50ms | 故障 fail-closed（安全） |
| 证明服务（G2.1） | 可用性 / 证明延迟 | 99.95% / P95 <100ms | 红线 R9.10 |
| 票据管理（G2.2） | 吊销生效时效 | 吊销 ≤1min（P99） | 红线 R9.9 |
| 删除传播（G3.1） | 删除完成时效 | 24h 内完成（P95） | 红线 R7.10/R11.13 |
| 联邦聚合（G4.1） | 任务完成率 | 99% 训练轮次完成 | 非实时 |
| 权重 OTA（G4.2） | 分发成功率 | 安装成功率 >98% | C6.4 §8 阈值 |
| 审计台（G5.1） | 采集不丢 / 查询可用 | 采集 >99.99% / 查询 99.9% | 审计链不丢 |
| 数据留存/合规（G3.2） | 清理作业按时执行 | 100% 按时 | 批作业 |

### 3.2 错误预算

```
错误预算 = 100% - SLO
  月度 99.9% → 错误预算 43.8 分钟/月
  使用：SRE 与发布团队共享；错误预算耗尽 → 冻结高风险发布（回滚优先）
```

## 4. 日志留存策略（对齐 G3.2 数据分类）

| 日志类 | 内容 | 敏感度 | 留存 | 存储 |
|---|---|---|---|---|
| **运行日志** | 服务 stdout/错误栈/请求追踪（脱敏） | 低-中 | 30 天热 + 180 天冷 | 日志集群 |
| **审计日志** | G5.1 审计摘要（无正文） | 中 | 180 天（可配置，G3.2） | 审计链存储 |
| **遥测日志** | 指标/用量/性能（聚合） | 低 | 90 天（对账期） | 指标库 |
| **安全事件** | 异常/告警/响应记录 | 中-高 | 365 天 | 安全存储 |
| **发布/回滚记录** | OTA 发布清单/回滚 | 低 | 365 天 | 版本库 |
| **正文/样本** | — | 高 | **不落盘**（G3.1/G3.2） | — |

> 日志脱敏：运行日志强制脱敏（不落 PII/正文，对齐 G1.3）；日志访问按角色审计。

## 5. 监控与告警

### 5.1 监控面

| 面 | 指标（示例） |
|---|---|
| 服务健康 | 可用性、错误率、5xx 占比、进程/依赖状态 |
| 性能 | P50/P95/P99 延迟（首 token/配额检查/证明/脱敏/删除任务） |
| 容量 | QPS、并发、队列积压、存储水位、GPU/CPU 利用率 |
| 业务 | 请求量、用量（token/成本）、删除 SLA 达标率、OTA 成功率 |
| 安全（G5.1） | 告警量、检测器命中、吊销时效 |

### 5.2 告警分级

| 级别 | 条件 | 响应 |
|---|---|---|
| P1（critical） | 可用性 <SLO、数据丢失风险、安全事件（G5.1 critical） | 立即响应（值班 15min 内），止损优先 |
| P2（high） | 延迟超标、错误率上升、删除 SLA 风险 | 30min 内响应 |
| P3（warning） | 容量水位预警、错误预算消耗过快 | 工作日处理 |
| P4（info） | 常规变化 | 记录 |

---

## 6. 事故管理流程

```
检测（监控/G5.1 告警）
  → 1. 分级（P1-P4）
  → 2. 响应：值班接管，SOP 执行（止损 > 根因 > 恢复）
  → 3. 止损：回滚/限流/切换地域/降级（fail-open/fail-closed 按设计）
  → 4. 恢复 + 验证（SLO 恢复）
  → 5. 复盘（blameless postmortem，48h 内初稿）：
       - 时间线 / 根因（5-whys）/ 影响面（用户量/损失）
       - 改进项（预防/检测/响应）→ 指派 owner + 截止日期
  → 6. 改进闭环：改进项跟踪到关闭；错误预算扣减记录
```

## 7. 容量规划

### 7.1 容量模型

```
容量需求 = f(设备规模, 每设备日请求量, 峰值系数, 用量增长趋势)
  输入：
    - 设备注册量（G2.1 注册表）
    - 每设备日云端请求量（G5.1 用量统计）
    - 高峰系数（典型 3-5× 日均）
    - 联邦/OTA 批量任务峰值
  输出：
    - 各服务（Broker/AS/配额/脱敏/删除/审计）QPS、存储、网络预算
    - 上游模型供应商容量（token 配额）预留
```

### 7.2 扩容预案

| 触发 | 动作 |
|---|---|
| Broker QPS > 60% 水位 | 水平扩容副本（无状态） |
| 上游 token 配额 < 2 周余量 | 采购/预留（供应商沟通） |
| 存储水位 > 70% | 扩容 + 清理作业检查（G3.2） |
| 联邦批次高峰 | 预注册容量 + 错峰调度 |
| 大促/新市场开服 | 提前 1 个月演练 + 容量预留 |

### 7.3 成本优化

- 用量监控（G5.1）→ 模型档位优化（G1.2 lite/pro 占比调整）。
- 缓存命中率优化（路由表/配额缓存）。
- 空闲容量回收（按地域水位动态缩容）。
- 成本报表月度复盘（对齐 H5.1 遥测）。

## 8. 部署形态

- SRE 体系 = 监控栈（指标/日志/追踪）+ 告警路由 + 值班工具 + 事故平台 + 容量看板。
- 监控数据地域驻留（对齐 G3.2）；跨地域聚合仅摘要级。
- 与 G5.1 审计台共享事件总线；与 H5.1 KPI 遥测（端侧）联合成"端云统一可观测"。
- 值班轮值（SRE 团队）；P1 事件 7×24。
