## 0. 结论摘要

AI 披露与跨境数据流合规评审结论为 **有条件通过**。透明披露策略（端侧 AI 行为 + AI 生成内容标识）方向正确；CloudBroker 出域最小化已由 E2.3/E3.2 冻结基线覆盖；**联邦学习「数据不出设备」主张需要有条件核验**（见 §2.3，端侧数据不出设备 ✅，但「模型更新 / 梯度 / 聚合后信息」存在间接出域面，必须补披露与差分隐私）；隐私政策需要按 PIPL/GDPR 结构化补全。存在 4 项强制落地项：

1. **F1（AI 披露落地）**：端侧所有 AI 行为（接管通话/备忘收声/通知摘要/AI 语音）必须向用户透明披露 + AI 生成内容按《标识办法》显式标识；**披露是产品级强制**，不因「本地处理」豁免。
2. **F2（出域最小化固化）**：CloudBroker 出域只走 E2.3 字段白名单 + E3.2 F2/F4 脱敏中间件；**跨境出域**（若数据跨境）必须符合 PIPL 跨境提供规则（单独同意/标准合同/认证）——**v1 默认数据不出境**（部署地域内处理）。
3. **F3（联邦学习主张核验）**：「数据不出设备」主张**有条件成立**——原始数据不出设备 ✅，但须核验并披露：① 梯度/模型更新的信息泄漏面（差分隐私 + 梯度裁剪为强制项）；② 聚合服务（G4.1）不落原始数据；③ 微调样本的删除边界（对齐 E3.3 遗留项 2）。
4. **F4（隐私政策结构化）**：隐私政策按 PIPL（处理者/目的/敏感信息单独同意/权利行使/跨境/删除机制）与 GDPR（Art.13/14 通知要素）结构化编写，随版本 OTA 可查。

**评审底线**：**「本地优先」不等于「零披露」**——本地处理降低风险，但 AI 行为本身（在做什么、处理了什么）必须对用户透明；「数据不出设备」只覆盖原始数据，**梯度/模型更新/聚合产物**属于需要单独披露与管控的出域面。

## 2. 评审正文

### 2.1 透明披露策略

**评审结论：有条件通过（F1）**

- **披露范围**（端侧 AI 行为全覆盖）：
  - **AI 接管/代接**：对齐 E4.1 §3.2（AI 身份披露，向相对方）；
  - **备忘收声**：对齐 E4.3（预告/活性指示/录音态，向用户）；
  - **通知摘要/简报**：UI 标识「AI 摘要」来源（区分原生通知与 AI 生成摘要）；
  - **AI 语音（TTS）**：对外可感知的 AI 语音按《标识办法》音频标识要求（E4.1 §3.2）；
  - **决策类 AI（B5.3/B5.4 意图决策）**：高风险动作的决策依据在确认面板/仪表盘可查（对齐 D10 确认流，决策概率表冻结）。
- **披露形态**：
  - 实时（行为发生时）：活性指示器 + UI 文案（AI 身份/正在做什么）；
  - 事后（隐私仪表盘）：「AI 行为日志」（谁/何时/处理了什么数据/去向），联动 `IAgentAuditService` 脱敏流（D4 viewerRole=USER）。
- **《标识办法》落地**：AI 生成的**对外内容**（通话摘要、备忘摘要、AI 回复转发）须含显式标识（文本角标「AI 生成」/「AI 转写」）；本地即时 UI 场景用界面标识（不算对外传播，但用户可见即可）。

### 2.2 CloudBroker 出域最小化

**评审结论：通过（F2 固化 E2.3/E3.2 基线）**

- 出域字段 = E2.3 §2.2 白名单；脱敏中间件 = E3.2 F4（强制启用）；`privacyMode` 违反即拒。
- **跨境维度（新增，F2）**：
  - **v1 默认数据不出境**：CloudBroker 部署在地域内（中国首发 → 境内节点），`deviceKeyHash`/`contextDelta` 不跨地域路由；
  - 若未来开启跨境（多地域 broker）：须满足 PIPL 第 38-40 条（单独同意 + 告知接收方/用途 + 标准合同/安全评估或认证），且按 E2.3 白名单域「每个地域的 broker 域名单独登记」；
  - **禁止**：为「就近路由」而把脱敏前数据跨域（最小化优先于延迟）。
- **审计**：每次 TIER_CLOUD 记地域信息（`EgressPlan` 增加 `region` 字段建议），隐私仪表盘「云使用」可见数据去向地域。

### 2.3 联邦学习「数据不出设备」主张核验

**评审结论：有条件成立（F3）**

- **主张**：「联邦学习数据不出设备」（G4.1 联邦微调聚合服务，D13 §6 模型更新走签名包 OTA）。
- **核验结论**：
  1. **原始数据不出设备：✅ 成立**——训练在端侧完成，原始样本不离开设备（端侧 `IAgentMemoryService` 数据不参与上传，模型权重更新上传）。
  2. **梯度/更新出域面：⚠️ 存在间接出域**——上传的模型更新/梯度可被推断训练数据分布（模型反演/成员推断攻击）。**强制措施**：
     - 差分隐私（DP）：梯度裁剪 + 噪声注入（DP-SGD），提供 ε/δ 预算声明；
     - 梯度聚合：安全聚合（secure aggregation）/ 至少服务端只见聚合后结果（G4.1 设计约束）；
     - 防中毒审计：聚合服务校验更新来源与偏离度（G4.1，WBS 已含）；
     - 更新内容审查：权重 OTA 签名 + 可信启动同款校验（D13 §6）。
  3. **聚合产物的删除边界：⚠️ 需披露**——聚合后模型无法「单独删除某用户贡献」（E3.3 遗留项 2 联动），隐私政策必须披露「聚合模型的不可逆性」。
  4. **主张修订**：对外主张应从「数据不出设备」修订为「**原始数据不出设备，模型学习以差分隐私保护的可验证方式聚合，聚合模型不可逆**」——这是可核验、可披露的准确表述。

### 2.4 隐私政策

**评审结论：有条件通过（F4）**

- **结构要求**（PIPL + GDPR Art.13/14 对齐）：
  | 章节 | PIPL | GDPR |
  |---|---|---|
  | 处理者身份/联系方式 | 第 17(1) | Art.13(1)(a) |
  | 处理目的/方式/范围 | 第 17(2-3) | Art.13(1)(c) |
  | 敏感个人信息（单独同意） | 第 29-30 条 | Art.9 |
  | 录音/通话/备忘收声 | 对齐 E4.1/E4.3 结论 | — |
  | 跨境提供 | 第 38-40 条 | Art.44-49 |
  | 用户权利（查阅/更正/删除/撤回同意/注销） | 第 44-50 条 | Art.15-22 |
  | 删除机制 | 对齐 E3.3（forget/24h SLA/聚合不可逆） | Art.17 |
  | 联邦学习主张 | 用 §2.3 修订后表述 | — |
  | 儿童/未成年人 | 第 31 条 | Art.8 |
- **呈现**：隐私政策随系统版本 OTA（`Settings` 内可查 + 首次设置向导摘要 + 敏感能力首次使用时的「点对点告知」），版本化可回溯。
- **点对点告知**：录音（E4.1）、备忘收声（E4.3）、位置（D8 coarsePlace）、云推理（TIER_CLOUD）——每个敏感能力首次启用时给「该能力会用哪些数据/去往哪里/如何删除」的定向告知 + 授权（对齐 PIPL 单独同意精神）。

## 4. 验收口径

- [ ] 各 AI 行为场景披露用例通过（接管/备忘/摘要/AI 语音/决策）。
- [ ] AI 生成对外内容含显式标识。
- [ ] 出域请求只走白名单字段 + 中间件；v1 无跨境路由（地域字段验证）。
- [ ] 联邦学习：DP 参数（ε/δ）声明 + 梯度聚合校验 + 防中毒审计日志存在；主张文案已修订。
- [ ] 隐私政策结构对照表全项覆盖（PIPL/GDPR）。

## 5. 遗留项

1. **DP 预算与模型质量的权衡**：ε/δ 参数随 G4.1 实测收敛（对齐 WBS G4.1 A5 里程碑）。
2. **多地域 broker 的跨境合规**：若 A4+ 开启，按 PIPL 跨境规则补充（标准合同/评估）。
3. **第三方 Agent 自带模型的披露**：三方远端模型端点（D14）出域同样披露 + preflight 约束（联动 E5.3 沙箱网络白名单）。
4. **AI 生成内容的传播链标识**：用户转发 AI 摘要/回复到社交平台的标识保留（随对外分享功能评估）。
