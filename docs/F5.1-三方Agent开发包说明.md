## 1. 什么是三方 Agent SDK

三方 Agent = **非平台签名的独立开发者 Agent**（如第三方 AI 助理/插件）。它**没有任何平台签名特权**，
一切系统能力只能经"沙箱网关"的受限操作面获得（D14 红线①）。

开发包构成：

| 组件 | 位置 | 说明 |
|---|---|---|
| SandboxManifest 模板 | `vendor/genton/templates/SandboxManifest.template.json` | 能力与边界声明模板（含字段注释） |
| SandboxManifest Schema | `vendor/genton/templates/sandbox-manifest.schema.json` | 清单校验 JSON Schema |
| 联调样例 | `vendor/genton/templates/sample-agent/` | 最小示例 Agent（F5.2） |
| 合规指引 | `docs/F5.2-三方沙箱合规指引.md` | 授权 UI 走查、能力撤销、deny 默认、审计透明 |

核心概念：**你的 Agent 是一个声明 + 一个实现** —— 用 `SandboxManifest` 声明"想要什么能力"，
实现 `ISandboxedAgent` AIDL 接口，宿主（B6.1）负责隔离与授权，网关（B6.2）负责把每次调用映射到完整策略链。

---

## 2. 接入总流程

```
1. 编写 SandboxManifest.json（能力最小化声明）
2. 本地校验（schema / 能力名 / 域名 / 预算）
3. 实现 ISandboxedAgent + 网关调用（经 IAgentSandboxGateway）
4. 打包 APK（isolatedProcess 服务）
5. 提交签名与清单 → 用户安装 → 首启授权向导（逐项确认，deny 默认）
6. 沙箱启动（startSandbox 校验授权）→ 运行 → 随时可撤销
```

## 3. SandboxManifest 怎么写

以 `SandboxManifest.template.json` 为起点，逐字段说明如下（对齐 D14 §2 与 B6.1 校验流程）：

### 3.1 身份与签名

| 字段 | 必填 | 说明 |
|---|---|---|
| `sandbox_agent.id` | ✅ | 全局唯一 ID，`<pkg>.agent` 形式（如 `com.example.gptmate.agent`） |
| `sandbox_agent.name` | ✅ | 面向用户显示名（授权 UI / 隐私仪表盘展示） |
| `sandbox_agent.developer` | ✅ | 开发者标识 |
| `sandbox_agent.version` | ✅ | 清单版本（**能力声明变化必须自增**） |
| `sandbox_agent.signature_ref` | ✅ | APK 签名引用；**发布前必须**填签名证书指纹（sha256-…），系统校验不匹配则 `STATUS_UNSIGNED` |
| `sandbox_agent.sandboxed` | ✅ | **固定 `true`**（ACB 注册强制项），`false` 被拒 |

### 3.2 模型端点（只能用自己的远端模型）

```json
"model": {
  "endpoints": [
    { "domain": "api.example.com", "protocol": "https", "attestation": "not_required" }
  ]
}
```

- 系统本地模型（B5.x）**不对三方开放**；你只能用清单内声明的远端模型端点；
- `domain` 必须同时出现在 `network_domains`；
- `attestation`：D14 开放问题 1 当前信任清单域名（`not_required`）；A5 若启用端点证明需改 `required`。

### 3.3 能力申请（逐项授权、deny 默认）

```json
"requested_capabilities": [
  { "capability": "agent.input_inject", "risk": "low", "purpose": "代操作简单界面" },
  { "capability": "events.read", "risk": "low", "purpose": "通知摘要", "types": ["notification.posted"] },
  { "capability": "agent.memory.own", "risk": "medium", "purpose": "读写自身记忆" }
]
```

- `capability` 必须命中**策略引擎能力清单**（A7.1 基线）与**网关 5 OP 白名单**（B6.2）：
  - `agent.ui.read_masked` → OP_UI_READ_MASKED（掩码 UI 摘要）
  - `agent.context.read` → OP_CONTEXT_READ（受限上下文帧）
  - `agent.memory.own` → OP_MEMORY_OWN（自身记忆，own_only）
  - `agent.input_inject` / `agent.ui_navigate` / `agent.gesture` → OP_ACTION_REQUEST（动作走策略链）
  - `events.read` + `types` → OP_EVENTS_SUB（白名单事件子集）
- `risk`：low / medium / high。**high 一律走系统确认流**（B6.2），你的 Agent 会收到 `pending_confirmation`；
- `purpose` 必须**如实描述**用途 —— 这是用户授权的依据，虚报会导致合规问题（见 F5.2 合规指引）；
- **权限最小化**：只申请完成任务所需的最小能力集合（§5）。

### 3.4 记忆范围（own_only）

```json
"memory_scope": "own_only"
```

- **固定 `own_only`**：只读写自身记忆分区；系统记忆、他人 Agent、全局实体一律不可见（D14 权限矩阵）；
- 网关 `OP_MEMORY_OWN` 强制执行 agentId 隔离（B6.2 consumeMemoryOwn）。

### 3.5 出网域名白名单

```json
"network_domains": ["api.example.com"]
```

- netd iptables 默认 deny 沙箱 UID 所有出网，只放行白名单域名（B6.1 configureNetworkWhitelist）；
- 域名变化必须更新清单并**重新授权**（能力变化 → version++）。

### 3.6 预算（宿主强制）

```json
"budgets": {
  "cost_per_day_usd": 0.1,
  "max_walltime_ms_per_task": 60000,
  "max_calls_per_hour": 100
}
```

- 宿主代管强制（配额超限自动终止沙箱）；以网关记录为准，防三方虚报（D14 开放问题 5）；
- `max_calls_per_hour` 对齐 B6.1 默认配额（100 次/小时）。

### 3.7 可选字段

| 字段 | 说明 |
|---|---|
| `capability_ttl_ms` | 授权会话级 TTL（B6.1 授权模型：会话级 TTL），过期后需重新授权 |
| `sandbox_resources.cpu_percent` / `memory_mb` | cgroup 配额覆盖（缺省 CPU 10% / 内存 256MB） |

## 4. 如何随 B6 沙箱宿主交付

### 4.1 APK 打包（isolatedProcess 服务）

```xml
<manifest package="com.example.gptmate">
    <!-- 沙箱进程服务：宿主以 BIND_ISOLATED_PROCESS 绑定 -->
    <service android:name=".SandboxedAgentService"
             android:exported="true"
             android:isolatedProcess="true"
             android:permission="com.genton.permission.USE_SANDBOX">
        <intent-filter>
            <action android:name="com.genton.sandbox.ISandboxedAgent" />
        </intent-filter>
    </service>
</manifest>
```

> 注意：isolatedProcess 服务**无任何权限**（不含 signature|privileged），
> 系统侧已通过 SELinux `neverallow` 收紧（B6.1），你无需也不能申请特权权限。

### 4.2 清单随 APK 交付

- 将 `SandboxManifest.json` 放入 APK `assets/` 目录（约定路径 `assets/genton/sandbox-manifest.json`）；
- 系统安装/注册时读取并校验（schema + 签名 + 能力 + 域名 + 预算）；
- **联调阶段**：可先用 `adb push` 到 `/data/local/tmp/` 配合宿主测试入口加载。

### 4.3 实现 ISandboxedAgent

```kotlin
// 三方 Agent App 实现（宿主调用你）
class SandboxedAgentService : Service(), ISandboxedAgent {
    override fun start(context: SandboxSessionContext, events: IAgentSandboxHostEvents): Int { ... }
    override fun onUserMessage(turn: SandboxUserTurn): Int { /* 走你的远端模型 */ }
    override fun onToolResult(toolCallId: String, result: ToolResultEnvelope): Int { ... }
    override fun cancelCurrentTask(): Int { ... }
    override fun stop(reason: Int): Int { ... }
}
```

- 所有"动作"必须经网关 `IAgentSandboxGateway`（示例见 F5.2 `sample-agent/`）；
- 你**不能**直接 bind 任何系统服务接口（签名权限拒绝）。

### 4.4 生命周期

```
安装 → 首启授权向导（用户逐项确认）→ 授权落策略引擎（USER_ALLOW_TASK 同级持久条目）
  → startSandbox(manifest) 校验授权 → SandboxHandle
  → ISandboxedAgent.start(ctx) → onReady → 会话
  → 用户 revokeConsent（一键撤销）→ 令牌即时失效（≤100ms）→ 沙箱停止 + 审计
```

---

## 5. 权限最小化（Least Privilege）

1. **只申请完成任务所需的最小能力**：例如只做"通知摘要"就不申请 `agent.input_inject`；
2. **低风险优先**：能读不写、能 low 不 high；high 能力意味着每次都要用户确认，体验与合规成本都高；
3. **事件订阅收窄**：`events.read` 必须带 `types` 子集，禁止通配（D14：无通配符/S2 位置类）；
4. **域名最小化**：模型端点与业务端点分开声明，不用的域立即移除；
5. **版本即边界**：任何能力/域名的增加都要 `version++` 并重新过授权 UI —— 这是"能力变化不可静默发生"的机制保障。

## 6. 能力撤销（Revocation）演示与语义

见 `docs/F5.2-三方沙箱合规指引.md` §3。要点：

- 用户可在隐私仪表盘 **一键撤销（revokeConsent）**，撤销即时生效（≤100ms，B6.1 R10.8）；
- 撤销后：所有受保护网关操作返回 `STATUS_DENIED`；沙箱停止；审计记录撤销事件；
- 你的 Agent 收到 `stop(reason=REVOKED)` 时应清理本地状态，不得重试已撤销操作；
- **撤销不可静默绕过**：重新使用必须重新走首启授权向导。

### 7.1 清单校验

```bash
# 结构校验（JSON 可解析 + 必需字段存在）
python -c "import json; json.load(open('SandboxManifest.json', encoding='utf-8')); print('JSON OK')"

# 在 CI 中用 jsonschema 校验 vendor/genton/templates/sandbox-manifest.schema.json
```

### 7.2 常见错误码（对齐 B6.1 / D14）

| 错误码 | 含义 | 处理 |
|---|---|---|
| `STATUS_UNSIGNED` (2) | 签名/清单校验失败 | 检查 signature_ref 与 APK 签名 |
| `STATUS_DENIED` (1) | 能力未授权 / 令牌失效 | 检查授权记录；用户可能已撤销 |
| `STATUS_OVER_QUOTA` (3) | 预算超限 | 检查 budgets；等待窗口重置 |
| `STATUS_NOT_FOUND` (2, A8.1) | 资产不存在 | 检查 assetId 与注册状态 |

### 7.3 联调要点（标注占位项）

- `signature_ref` 在联调阶段可为占位符，**发布前必须替换**为真实指纹；
- `model.endpoints` 的域名需与你的实际模型 API 一致（联调时核对出网白名单命中）；
- `requested_capabilities` 中能力名需与当前策略引擎能力清单一致（联调时与 B 部门核对，D14 能力名以系统为准）。
