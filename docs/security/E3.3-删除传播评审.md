## 0. 结论摘要

遗忘与删除传播评审结论为 **有条件通过**。设计语义（`forget` 级联删除记忆+实体+云端、图级删除、24h 云端 SLA、撤销记录）方向正确且与 D4/D6/D13 契约一致。存在 3 项强制落地项：

1. **F1（级联完整性）**：`forget(topic=X)` 必须级联覆盖「记忆条目 + 向量索引 + 图谱节点/边 + 工作记忆引用 + 云端副本」，任何一级遗漏都视为删除不完整（`ForgetJob` 必须报告各域删除统计并可复验）。
2. **F2（图级删除语义）**：实体删除必须是图级（删除实体节点 + 全部关联关系边 + 依赖该实体的记忆条目），并处理「多实体共享记忆」的引用计数——删除不完整时 `ForgetJob.status=failed` 并给出残留清单。
3. **F3（云端删除 SLA 与撤销记录）**：云端删除传播 **24 小时内完成**（R11.13），broker 回执**可审计删除证明**（含内容指纹 + 时间戳 + 签名）；删除操作记 `CAT_MEMORY_ACCESS` 撤销记录（含 jobId/统计/云端状态），**审计链记录不可删但可 tombstone 化**（R11.14 + R2.13 平衡）。

**评审底线**：
- **审计链不因删除而丢**（R2.13/R8.4）：删除本身是审计事件，记录必须保留（tombstone 语义），但**正文/证据可删**（D4 §7.2 证据分离）。
- **「忘记」不等于「隐藏」**：用户 forget 是真实删除意图，不得退化为「soft delete + 界面隐藏」——除非在 UI 明示保留期（如撤销窗口）。

## 2. 评审正文

### 2.1 记忆 forget 级联

**评审结论：有条件通过（F1）**

- **现状**：D4 定义 `ForgetRequest{topic, includeWorking, includeSystem, reason, confirmCloudDeletion}` 与 `ForgetJob{jobId, status, deletedLocalCount, deletedVectorCount, cloudSyncPending, error}`；`forget` 为异步任务，结果经 `onForgetCompleted` 回传。
- **级联范围评审**（F1 明确必须覆盖）：
  1. **记忆条目**：`LONG_TERM` 中 entity/topic 匹配的条目（`deleteById` 逐个或批量）；
  2. **向量索引**：对应 embedding 节点（`deletedVectorCount`）；
  3. **图谱节点/边**：实体节点 + 关系边（联动 F2）；
  4. **工作记忆引用**：`WORKING` 中引用该实体的内容（默认随会话过期，但若引用仍在活跃会话中应标记失效）；
  5. **云端副本**：`confirmCloudDeletion=true` 时同步删除凭证推云端（G3.1）；
  6. **模型微调缓存**：若该内容进入过联邦微调样本（D13 §5「若在保留窗口内」），云端须一并清除。
- **可复验性**（F1 关键）：
  - `ForgetJob` 增加 `deletedEntityCount`、`deletedRelationCount`、`residualCount`（残留数）字段（建议补档 D4）；
  - 完成回调后，隐私仪表盘可执行**复验查询**（`query(entity=X)` 返回空 + 图谱 `find(X)` 返回空）确认删除完整；
  - 复验失败（残留）→ `ForgetJob.status=failed` + `error` 列出残留引用，UI 明示「未完全删除」。

### 2.2 实体图级删除

**评审结论：有条件通过（F2）**

- **现状**：D6 本体层（`IEntityQueryService`）管理 `Entity`/`RelationEdge`；「忘记= X 图级删除」是架构 §6 隐私层的既定语义。
- **图级删除语义评审**：
  - 删除实体 E 时：① 删除 `E` 节点；② 删除所有 `RelationEdge(从 E 出发/指向 E)`；③ 删除依赖 E 的记忆条目（对齐 F1）；④ 触发 `semantic.entity_updated`/`semantic.memory_page_invalidated` 事件（D7 语义组），使预打包/上下文缓存失效；
  - **共享引用处理**：一条记忆同时引用实体 E1 与 E2 时，删除 E1 后该记忆如何处置？评审裁决：**引用计数归零才删记忆**；仅 E1 被删时，记忆保留但移除 E1 的引用与相关片段（不整条删除）——需在 D4/D6 契约中明确 `unlink` 语义；
  - **幂等性**：重复 forget 同一实体 → 第二次返回已删（STATUS_OK + 计数 0），不得报错或产生重复删除事件。
- **验收**：用例「删除实体 → 图谱 find 为空 + 关系边清零 + 关联事件已发 + 幂等」。

### 2.3 云端删除传播 SLA

**评审结论：有条件通过（F3）**

- **现状**：D13 §5「忘记 X 时设备向 broker 发删除凭证，broker 删除缓存与微调样本（若在保留窗口内）」；R11.13「云端删除传播必须在 24 小时内完成」。
- **SLA 评审**：
  - **目标**：`forget` 发起 → 云端副本删除完成 ≤ 24h（红线 SLA）；
  - **内部分档**（建议更严，随 G3.1 落地）：
    - 云端缓存/短期副本：≤ 2h；
    - 云端长期存储/微调样本：≤ 24h（若在保留窗口内）；
  - **删除凭证**：设备 → broker 的删除凭证含 `topic/contentFingerprint（内容哈希）+ forgetJobId + 时间戳 + 设备签名`；broker 回执 `deletionReceipt{jobId, deletedItems, fingerprintList, timestamp, brokerSignature}`（D13 开放问题 6 裁决：**回执必须可审计可验证**）；
  - **对账**：设备侧保留 `ForgetJob.cloudSyncPending` 状态，直到收到回执；超时未回执 → 重试 + 仪表盘「云端删除待确认」提示。
- **验收**：用例「forget → 云端副本 24h 内删除 + 回执签名可验 + 复验（云端查询为空）」。

### 2.4 撤销记录完整性

**评审结论：有条件通过（F3）**

- **现状**：R11.14「删除操作必须记录撤销日志」；D4 审计 `CAT_MEMORY_ACCESS` 含 memory read/write/forget 事件。
- **撤销记录要求**（F3）：
  - 每次 forget/delete 写审计事件：`category=CAT_MEMORY_ACCESS`、`summary="用户发起忘记:客户A"`、`payloadHash=内容哈希`（**不记明文**，R4.2）、`evidenceRefs` 指向 `ForgetJob` 详情（可含统计）；
  - **审计链不可删除**（R2.13/R8.4）：删除操作本身是审计事件，**审计记录保留**；「删除证据（截图/音频）」时审计链留 tombstone（D4 §7.2）；
  - 撤销窗口：若提供「撤销删除」（如 7 天回收站），UI 必须明示保留期与到期物理删除，且**用户 forget 的撤销窗口默认关闭**（forget=真实删除，除非用户主动启用回收站）；
  - 敏感数据物理清零（R11.15）：删除的记忆正文若曾加密（密钥在 TEE），删除密钥或覆写密文；证据文件删除后不可恢复（fstrim/overwrite）。
- **验收**：用例「forget 后审计链含删除事件（摘要级，无明文）；删除事件不可删（尝试 update/delete 被拒）；证据删除后 tombstone 存在」。

### 2.5 敏感数据物理清零

**评审结论：通过（需落地细节）**

- 记忆正文加密（密钥在 TEE 域，D4 §2.1）——删除时**销毁该条目的数据加密密钥**（KEK 派生、条目级 DEK），使密文不可解密（等效物理删除，比覆写更可靠）；
- 证据文件（截图/录音）：删除后不可恢复（覆写 + 触发 fstrim；录音文件在 D9 §8.1 备忘收声场景的删除语义联动 E4.3）；
- **云端**：云侧删除同样「密钥销毁 + 覆写」，不得只软删。

## 4. 验收口径

- [ ] `forget("客户A")` 后：记忆 query 空 + 图谱 find 空 + 向量索引清除 + 云端副本 24h 内删除（回执可验）。
- [ ] 实体删除：关系边清零、关联事件已发（`semantic.entity_updated`）、幂等（二次 forget 返回已删）。
- [ ] 删除传播 SLA：缓存 ≤2h、长期/微调 ≤24h；超时重试 + 仪表盘提示。
- [ ] 撤销记录：审计链含删除事件（摘要级、payloadHash）、删除事件不可删、证据 tombstone。
- [ ] 敏感数据：条目级 DEK 销毁、证据覆写 + fstrim、云端同口径。

---

## 5. 遗留项

1. **删除凭证的时效与吊销**：凭证本身过期/吊销机制（防重放删除），联动 E2.3 票据体系。
2. **联邦微调样本的删除边界**：样本进入聚合后的「不可删除」问题——差分隐私聚合后单体样本不可逆，需在 E4.2 联邦学习评审中定义「聚合后不可单独删除」的披露口径（R11.15 边界）。
3. **回收站（撤销窗口）设计**：若提供，UI 明示保留期与物理删除，默认关闭。
4. **跨设备删除**：多设备同步场景（若有）的删除传播——v1 仅单设备 + 云端，多设备列 A5 预研。
