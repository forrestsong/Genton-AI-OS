# G1.3 出端脱敏与最小字段中间件设计

> **任务编号**：G1.3
> **任务名称**：出端脱敏与最小字段中间件（PII 扫描剥离、字段白名单、摘要化）
> **交付物**：脱敏中间件
> **前置依赖**：G1.1（CloudBroker 网关）、E3.2（数据最小化评审）
> **草案来源**：D13（轨道A-端云调度与推理路由接口草案.md §5 数据离开策略）、E3.1（PII 掩码验收基准）
> **里程碑**：A3（智能与端云）
> **状态**：设计稿（待实现）

---

## 1. 摘要

出端脱敏与最小字段中间件是**云端侧的强制脱敏闸门**：所有进入 CloudBroker 的请求正文在到达模型供应商之前，必须经过本中间件处理，确保：

1. **PII 扫描剥离**：按 E3.1 三大敏感类别（金融/健康/账号）检测并剥离/掩码 PII；漏网 PII 由云端规则库兜底（端侧掩码模型 C4.3 的云端镜像）。
2. **字段白名单**：请求只允许携带 D13 定义的最小字段集（`deviceKeyHash / contextDelta / privacyMode / budget` + 推理必要字段），超白名单字段剥离或拒绝。
3. **摘要化**：按 `privacyMode`（`plain / masked / summarized`）对上下文做三级处理；敏感内容优先摘要化而非原文外发。

中间件与端侧 `preflightEgress()` 生成的 `EgressPlan` 形成**双端一致的脱敏契约**：端侧承诺脱敏 → 云侧强制校验（脱敏声明与内容一致性抽检），违反即拒（`FIELD_VIOLATION` / `PRIVACY_VIOLATION`）。

---

## 2. 职责

| 职责 | 说明 |
|---|---|
| PII 扫描 | 云端规则库 + 掩码模型双通道检测：规则库（正则/Luhn/词表，镜像 E3.1）优先、模型（云端版 C4.3 掩码模型）兜底；命中即剥离/掩码 |
| 字段白名单强制 | 请求 schema 白名单校验：超字段剥离（去重后仍超 → 422 拒绝） |
| 摘要化 | `privacyMode=summarized` 时用云端摘要模型压缩上下文（保语义去 PII）；`masked` 时仅掩码；`plain` 仅在白名单场景允许 |
| 一致性校验 | 校验端侧 `privacyMode` 声明与内容实际脱敏程度；声明 `masked` 却含明文 PII → `PRIVACY_VIOLATION` |
| 脱敏审计 | 每次脱敏动作（扫描条数/剥离字段/掩码类型）产生审计摘要（G5.1 → A5.3） |
| 摘要化回写 | 摘要化后的上下文以 `contextDelta` 引用形式供模型消费；原始内容处理即弃 |

## 3. 接口契约

### 3.1 脱敏检查/处理端点（Broker 内部中间件；对外可观测接口）

端点：`POST /v1/privacy/redact`（Broker 内部调用；设备不可直接调用）

```json
{
  "requestId": "req_01HZ...",
  "deviceKeyHash": "sha256:9f2c...b1e0",
  "privacyMode": "masked",            // plain | masked | summarized
  "content": {
    "prompt": "帮我给客户张三转账 5000 元，他的卡号是 6222 0012 3456 7890",
    "context": { "type": "kv_session", "refId": "kv_9a...", "deltaFields": ["currentScreenSummary"] }
  },
  "fields": ["prompt", "context"]
}
```

响应：

```json
{
  "requestId": "req_01HZ...",
  "result": "OK",                       // OK | REJECTED
  "redacted": {
    "prompt": "帮我给客户[客户1]转账 5000 元，他的卡号是 6222 **** **** 7890",
    "maskedFields": ["prompt"],
    "piiDetections": [
      { "type": "bank_card", "count": 1, "action": "partial_mask" },
      { "type": "person_name", "count": 1, "action": "entity_mask" }
    ]
  },
  "fieldsToSend": ["prompt", "context"],
  "fieldsStripped": ["metadata.imei"],
  "auditSummary": {
    "scanCount": 12,
    "maskedCount": 2,
    "strippedCount": 1,
    "summarized": false
  }
}
```

拒绝时（声明与内容不符）：

```json
{
  "requestId": "req_01HZ...",
  "result": "REJECTED",
  "error": { "code": "PRIVACY_VIOLATION", "message": "privacyMode=masked 但检测到明文手机号" },
  "statusCode": 422
}
```

### 3.2 摘要化模式

`privacyMode=summarized` 时，中间件先 PII 剥离，再用摘要模型压缩：

```json
{
  "privacyMode": "summarized",
  "content": { "prompt": "（原始 3000 字对话上下文，含金额/日程/地点）" }
}
```

```json
{
  "result": "OK",
  "redacted": {
    "prompt": "【摘要】用户需在明天 15:00 前完成一笔转账安排，金额量级为万元，收款人信息已脱敏。",
    "summarized": true,
    "originalTokens": 3000,
    "summarizedTokens": 120
  }
}
```

## 4. 脱敏策略表

| 类别 | 子类（E3.1） | 动作 | 掩码形态 |
|---|---|---|---|
| 金融 | 银行卡号 | 部分掩码 | `6222 **** **** 7890`（Luhn 验证） |
| 金融 | CVV/支付密码 | 全掩码 | `***` |
| 金融 | 金额 ≥10000 | 保留量级 | `¥1****` |
| 金融 | 交易流水号 | 全掩码或保留前后缀 | `TXN****7890` |
| 健康 | 身份证/护照 | 部分掩码 | `1101**********1234` |
| 健康 | 诊断/药品（敏感词表） | 全掩码/大类保留 | `**感染` |
| 健康 | 基因序列 | 全掩码 | `<redacted>` |
| 账号 | 手机号 | 部分掩码 | `138****5678` |
| 账号 | 邮箱 | 部分掩码 | `u***@example.com` |
| 账号 | IP/MAC | 全掩码 | `<redacted>` |
| 实体 | 人名/机构名（本体层 S4） | 实体掩码 | `[客户1]`（保持引用一致性） |
| 安全值 | 密码/OTP/凭据值 | **全掩码 + 剥离** | 值不出安全路径（红线 5） |

## 5. 字段白名单（最小字段）

| 字段组 | 字段 | 说明 |
|---|---|---|
| 身份 | `deviceKeyHash` | 设备公钥哈希（SHA-256），非设备 ID |
| 上下文 | `contextDelta` | 增量引用（packId/kvSessionId/deltaFields），不整包重传 |
| 隐私 | `privacyMode` | plain/masked/summarized 脱敏声明 |
| 预算 | `budget` | costCeilingMicros/maxTokens |
| 推理 | `model`, `input`（已脱敏）, `max_output_tokens`, `stream` | 推理必要字段 |
| 会话 | `sessionId`, `ticket`（鉴权头） | 会话标识 |
| **禁止** | `imei`, `serial`, 完整设备 ID, 明文密码/OTP, 原始音频（通话 R11.5）, 未脱敏正文 | 白名单外一律剥离/拒绝 |

> 白名单 schema 与端侧 `EgressPlan.fieldsToSend` 一致（同一权威：D13）；端侧 `preflightEgress` 已在本机剥离，云侧中间件为**第二道强制**。

## 7. 安全边界

- **强制启用不可旁路**：中间件是 Broker 请求管线的必经环节（红线 R7.9 "出网脱敏中间件必须强制启用"），设备无法跳过。
- **双通道检测**：规则库（确定性，E3.1 镜像）+ 云端掩码模型（召回兜底）；规则库先行保证敏感类别 100% 命中（R7.5）。
- **回退路径**：模型不可用时回退纯规则库（R7.3 掩码失败回退全屏掩码的云端对偶：检测不确定 → 保守全掩码）。
- **处理即弃**：脱敏前原始内容只存在于内存管线，不落盘；审计只含摘要。
- **摘要化不引入新 PII**：摘要模型输出二次过 PII 扫描（防摘要模型"重新拼出"PII）。
- **一致性即拒绝**：`privacyMode` 声明与内容不符 → `PRIVACY_VIOLATION`（422），宁可拒绝不过度放行。
- **性能**：PII 扫描 + 白名单 + 摘要 P95 ≤ 50ms（云端预算），不显著拖慢推理（对齐 E3.1 端侧 50ms 口径的云端镜像目标）。

## 8. 部署形态

- 中间件为 Broker 网关后的**独立服务**（无状态，水平扩容），与 Broker 同区域。
- 掩码模型为云端版 C4.3（GPU 推理集群），规则库以配置文件分发（版本化 + 签名，对齐资产/策略签名约定）。
- 摘要模型可复用上游模型或专用小模型（与 C4.4 ASR/TTS/摘要模型族同源，云端镜像）。
- 脱敏策略版本（`redactionPolicyVersion`）随路由表下发，保证端云策略一致。

## 9. 与端侧联动

| 端侧 | 联动点 |
|---|---|
| `preflightEgress()` → `EgressPlan` | 端侧字段清单/脱敏状态与云侧白名单/中间件一致；`fieldsMasked` 对齐 |
| `InferenceRequest.constraintsMask`（local_only） | 本地能办绝不出端；只有出网内容才经过中间件 |
| 端侧 PII 掩码（C4.3/感知层 maskPii） | 端侧第一道 + 云侧第二道，双保险（端侧漏网由云侧兜底） |
| `privacyMode` 声明 | 端侧声明脱敏等级 → 云侧一致性校验（违反即拒） |
| 审计（D4 `IAgentAuditService`） | 端侧 EgressPlan 摘要与云侧脱敏审计摘要通过 requestId 关联对账（G5.1） |
| 隐私仪表盘 | 端侧仪表盘可展示"云使用"字段清单与脱敏状态（D13 §3 透明） |

## 10. 验收口径

- [ ] E3.1 三大敏感类别（金融/健康/账号）云端检测命中率 ≥90%、敏感类别 100% 掩码（R7.4/R7.5）
- [ ] 出网请求只携带白名单字段；超字段剥离/拒绝（R7.6/R9.3）
- [ ] 中间件强制启用不可旁路（R7.9）
- [ ] `privacyMode` 一致性校验生效：声明 masked 却含明文 PII → 422 `PRIVACY_VIOLATION`
- [ ] 摘要化模式：摘要后二次 PII 扫描通过，摘要不泄露新 PII
- [ ] 脱敏处理 P95 ≤ 50ms（云端），不显著影响推理
- [ ] 脱敏动作全部落审计摘要（G5.1 → A5.3），requestId 与端侧 EgressPlan 可关联
- [ ] 掩码模型不可用时回退规则库，保守全掩码（R7.3 云端对偶）

## 11. 遗留项

1. **云端掩码模型版本**：云端版 C4.3 的评估集与端侧对齐方式（E3.1 评估集云端镜像）待定。
2. **实体掩码一致性**：`[客户1]` 式实体掩码需要跨请求保持同一实体映射一致（会话级实体表），避免摘要碎片化。
3. **多语言 PII 词表**：跨境场景（G3.2）需要英文/其他语言的 PII 规则补充。
4. **摘要化质量 KPI**：摘要保留语义的可测口径（下游任务效果回退率）需在实现期定义。
5. **与 E3.2 最小化评审联动**：中间件字段白名单需在 E3.2 评审结论落地后冻结。
