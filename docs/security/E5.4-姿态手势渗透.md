> **评审依据**：E1.1 红线（R12.1-R12.10 姿态交互、R8.8/R8.9 录音指示）、D9 §8（S7 MotionHub：意图就绪事件白名单/第三方不可读/三级档位/取消窗）、D7 事件流（订阅白名单/无通配符）、E4.3 备忘收声合规（取消窗/指示验收）、架构 §6

## 0. 结论摘要

本专项定义姿态手势（MotionHub，D9 §8）渗透攻击面的**四类测试**：第三方经事件流/传感器上下文推断手势语义、越权订阅「意图就绪」事件、取消窗绕过、录音态指示缺失。**核心判定：任何导致「第三方 Agent/App 推断出用户手势语义（摇一摇/翻面收声）」「越权订阅意图就绪事件」「绕过 3s 取消窗触发录音」「录音期间无指示」的攻击 = 高风险（阻断 A4）**。

**关键预检基线**（D9 §8.2/§8.4 + E4.3）：
- **MotionHub 是传感器上下文唯一常驻消费方**（R12.1），原始 IMU/遮挡状态不出服务；第三方与普通 App **不可读**手势语义与原始传感器上下文（R12.2，签名 + SE 收紧）；
- 仅向特权大脑出**摘要级「意图就绪」事件**，订阅走事件流白名单，**无通配符**（D7 §2）；
- 触发须「多传感器共识 + 场景白名单 + **3s 取消窗**」（D9 §8.3）；
- 录音期间**全局指示器常显**（R8.8/R8.9，复用 D3.2），不可被隐藏。

## 2. G1 手势语义推断（R12.6/R12.2）

### 2.1 用例 M1：事件流推断手势

| 项 | 内容 |
|---|---|
| 攻击步骤 | ① 第三方 Agent 订阅事件流，组合观察 `screen.on/off`、`foreground.changed`、`audio.route_changed`、`telephony.call_state` 等**非手势事件**；② 尝试关联推断「用户正在摇一摇/翻面静置」的时机 |
| 预期结果 | 事件流只下发摘要级负载（D7 §1）；**无任何事件暴露手势语义**（MotionHub 不出原始传感器/手势事件给第三方，R12.6）；即使组合推断，时间粒度与语义不可达 |
| 判定 | 通过 = 无法从事件流推断手势；失败 = 可推断「用户在做某手势」→ 高风险 |
| 验证 | 渗透脚本记录第三方可见事件全集，人工/模型评估是否含手势信息 |

### 2.2 用例 M2：传感器上下文直接读取

| 项 | 内容 |
|---|---|
| 攻击步骤 | ① 第三方 App 直接 `SensorManager` 注册加速度/陀螺仪传感器，尝试匹配摇一摇/翻转模式；② 或尝试 bind `IMotionHubService` 读原始上下文 |
| 预期结果 | R12.2：第三方不可直接读取 MotionHub（签名 + SE 收紧）；普通传感器**仍可读**（Android 原生能力无法完全屏蔽，但手势模式识别需高采样率权限 `HIGH_SAMPLING_RATE_SENSORS`——检查该权限是否被授予第三方；D9 §8.2 的「不可读」指 MotionHub 摘要服务，原始 IMU 属原生 Android 传感器面） |
| 判定 | 通过 = MotionHub 不可 bind + 高采样率传感器权限不给第三方（或给后手势判定仍无法对齐系统语义）；失败 = 第三方可经高采样率传感器精确复刻手势模式 → 高风险 |
| 注意 | 本用例是**半开放边界**：原生传感器面无法完全关闭（Android 平台约束），评审口径为「MotionHub 服务本身不可读 + 高采样率权限默认不给第三方 + 手势语义（摇=拍照就绪/翻面=收声）不被服务暴露」，剩余风险在权限授予处控制（联动 F5.1 三方 SDK 权限清单） |

### 2.3 用例 M3：传感器上下文 + 事件流联合推断

| 项 | 内容 |
|---|---|
| 攻击步骤 | ① 第三方组合「自己传感器读数 + 订阅到的系统事件（相机拉起/录音态/屏幕变化）」；② 推断用户姿态动作与「意图」 |
| 预期结果 | 系统事件不暴露「意图就绪」内容给第三方（G2 白名单）；相机/录音态 UI 变化是公开状态，但「就绪意图」语义只在特权大脑事件流 |
| 判定 | 通过 = 联合推断无法获得意图语义；失败 = 可推断意图 → 高风险 |

## 3. G2 越权订阅「意图就绪」事件（R12.7/D7）

### 3.1 用例 E1：第三方订阅 intent_ready

| 项 | 内容 |
|---|---|
| 攻击步骤 | ① 第三方 Agent 尝试 `IAgentEventStreamService` 订阅 `intent_ready`/`motion.*` 类事件（D9 §8.2「意图就绪」摘要事件）；② 尝试通配符订阅 `*` |
| 预期结果 | 「意图就绪」事件**不在第三方白名单**（D7 §2 事件类型白名单；MotionHub 摘要事件仅特权大脑经策略放行，D9 §8.2）；通配符订阅被拒（D7 红线②）→ `STATUS_INVALID_SUB`/`STATUS_DENIED` |
| 判定 | 通过 = 订阅被拒；失败 = 第三方可订阅意图就绪 → 高风险 |
| 验证 | 渗透脚本尝试订阅，断言返回拒绝 |

### 3.2 用例 E2：包过滤/敏感级事件越权

| 项 | 内容 |
|---|---|
| 攻击步骤 | ① 第三方尝试订阅 S2 级事件（`location.coarse_significant`）或经 `packageFilter` 收窄后订阅敏感事件 |
| 预期结果 | S2 事件默认关闭，需 capability + 用户开关 + 审计（D7 §2）；第三方 `memory_scope=own_only`、事件白名单 + 包过滤（D14 §4） |
| 判定 | 通过 = S2/敏感事件被拒；失败 = 可越权订阅 → 高风险 |

### 3.3 用例 E3：间接经宿主代理订阅

| 项 | 内容 |
|---|---|
| 攻击步骤 | ① 第三方经宿主大脑代理订阅意图就绪事件（把大脑当跳板）；② 或在宿主提示中注入「读取就绪状态」指令 |
| 预期结果 | 宿主（大脑）是特权消费方，但**第三方会话上下文不得包含就绪意图语义**（D9 §8.2 仅特权大脑）；提示注入由 taint/安检门拦截（R3.x）；宿主不得把就绪事件透传第三方 |
| 判定 | 通过 = 代理订阅/提示注入被拒；失败 = 经宿主间接获取意图 → 高风险 |

## 4. G3 取消窗绕过（R11.3/R12.10）

### 4.1 用例 C1：重复手势加速越过取消窗

| 项 | 内容 |
|---|---|
| 攻击步骤 | ① 触发备忘收声预告（3s 取消窗）；② 用户在窗内再摇一次/再翻一次面，试图「加速」直接进入录音 |
| 预期结果 | 取消窗**不可被任何新手势/重复手势绕过**（E4.3 F2）；窗内任何输入不改变「预告 → 取消/确认」流程；录音只在校验「窗内未取消」后启动 |
| 判定 | 通过 = 重复手势不绕过取消窗；失败 = 可加速越过取消窗 → 高风险 |

### 4.2 用例 C2：取消窗内无 UI / 取消无效

| 项 | 内容 |
|---|---|
| 攻击步骤 | ① 触发预告后立即把手机放口袋/锁屏，取消 UI 不可见；② 或点击取消但录音仍启动 |
| 预期结果 | 锁屏场景「提示先行 + 取消窗」补偿（D9 §8.5c）；取消按钮/手势在窗内任何时刻有效；取消后无文件/无索引（E4.3 F2） |
| 判定 | 通过 = 取消始终有效且无残留；失败 = 取消无效/仍录音 → 高风险 |

### 4.3 用例 C3：敏感场景绕过（R12.4）

| 项 | 内容 |
|---|---|
| 攻击步骤 | ① 通话中/支付页/输入聚焦/安全窗口在屏时做手势；② 尝试触发备忘收声/摇一摇就绪 |
| 预期结果 | 敏感场景强制全停手势（R12.4，D9 §8.3）；仅保留观察，不计误触发 |
| 判定 | 通过 = 敏感场景手势被禁；失败 = 敏感场景可触发 → 高风险 |

## 5. G4 录音态指示缺失（R8.8/R8.9/R11.4）

### 5.1 用例 R1：录音启动无指示

| 项 | 内容 |
|---|---|
| 攻击步骤 | ① 备忘收声启动；② 检查录音态指示是否在**启动瞬间**（<100ms）显示（E4.3 F2 验收口径） |
| 预期结果 | 录音态指示启动即显示（R8.8），状态栏芯片「● 录制中」+ 悬浮可停止 |
| 判定 | 通过 = 指示 ≤100ms 显示；失败 = 录音无指示 → 高风险 |
| 验证 | 高帧率录屏 + 时间戳比对（录音启动时间 vs 指示出现时间） |

### 5.2 用例 R2：Agent/App 隐藏指示

| 项 | 内容 |
|---|---|
| 攻击步骤 | ① 第三方 Agent 尝试隐藏/遮挡录音指示（通知栏操作、悬浮窗覆盖、请求隐藏状态栏）；② 或宿主大脑尝试关闭指示 |
| 预期结果 | 录音指示系统级独占（R8.9），Agent/App 无隐藏接口；第三方覆盖被拒（联动 E5.2 overlay 检测） |
| 判定 | 通过 = 指示不可被隐藏；失败 = 可隐藏/遮挡指示 → 高风险 |

### 5.3 用例 R3：指示与真实录音状态不一致

| 项 | 内容 |
|---|---|
| 攻击步骤 | ① 停止录音后指示仍显示（假象）；② 或指示显示但实际已录音（提前静默） |
| 预期结果 | 指示与 `IAgentAuditService` 活性流状态一致（D4 ActivityIndicator，R8.6 实时更新）；状态同步由审计活性流驱动 |
| 判定 | 通过 = 指示与状态一致；失败 = 状态不一致（可隐藏真实录音）→ 高风险 |

## 6. 门禁与执行

### 6.1 门禁口径

- E5.4 姿态渗透**无高风险** → A4 通过（WBS 里程碑矩阵 + 长链⑥）；
- D9.1/D9.2 呈现交付依赖 E5.4 + E4.3 通过；
- 中/低风险登记整改。

### 6.2 执行方式

- **真机**：实际执行手势（摇一摇/翻面静置），第三方 App/Agent 并行监测事件流/传感器/UI，验证 G1-G4；
- **静态扫描**：MotionHub 服务声明（权限/SE）、事件流白名单配置、指示器实现（SystemUI 独占）；
- **复用 `base_redteam.py`** 框架扩展 `motion_redteam.py`（A4 期补）。

---

## 7. 验收口径

- [ ] M1-M3：第三方无法从事件流/传感器/联合推断手势语义与意图。
- [ ] E1-E3：意图就绪事件订阅被拒（无通配符）；S2 事件越权被拒；代理订阅/提示注入被拒。
- [ ] C1-C3：取消窗不可绕过（重复手势无效）；取消始终有效无残留；敏感场景手势全停。
- [ ] R1-R3：录音指示 ≤100ms 显示、不可被隐藏、与真实状态一致。
- [ ] 联动：E4.3 F1-F4 验收通过（备忘收声告知/取消窗/指示/粗位置不出端）。

---

## 8. 遗留项

1. **`motion_redteam.py` 脚本化**：A4 期把 G1-G4 中可脚本化部分（意图就绪订阅拒绝、取消窗时序、指示状态一致性）脚本化，复用 `base_redteam.py` 框架。
2. **原生传感器面的残余风险**：第三方经原生 Android 传感器面（高采样率权限）复刻手势模式的能力——权限授予策略（F5.1 三方 SDK 权限清单）与手势模式识别鲁棒性的持续评估。
3. **机型差异登记**：无遮挡传感器机型的弱判定路径（D9 §8.5a）对手势渗透的影响随机型矩阵（A12.2 能力位）补充。
4. **指示状态与活性流一致性**：R8.6 活性流与录音指示的状态同步在低功耗/后台场景下的实测。
